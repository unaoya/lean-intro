- 前章からの問い: 実数とは何か（→ 実数は「構造」として与えられる。まず構造とは何か・Lean でどう書くかを掴む）
- 到達点: 「構造＝データ・class＝自動で見つかる構造」の見方を得る。Nat が core で持つ演算子クラス（Add/Mul/Zero/One/Sub/LE/LT）を「構造＝データ」として読む。一般構造で 1 回証明して複数インスタンスに適用する経験
- 新しい Lean 機能: structure キーワード・署名の読み方・暗黙引数（読む）・演算子クラス（Add 等＝記法の担い手）・class（最小: 自動解決される構造）
- コード: C02_Structures.lean（structure_as_data・nat_structures・general_proof・local_notation・And は structure）
- **役割分担**: この章は「構造の**機構**」——structure（データとしての構造）・Nat の裸の演算子クラス・一般化証明・class の概念。法則を被せた**階層**（モノイド→体→順序）と実数の公理は Ch3

## はじめに — この章で説明したいこと（章の地図）

- 自然数全体の集合は `Nat` という型に対応する
- Nat 上の二項演算はたくさんある（全体は `Map(N×N, N)` ＝ `N→N→N`）が、馴染みのあるものに通常の**加法**と**乗法**がある
- どちらも `(a+b)+(c+d) = (a+c)+(b+d)` を満たし、`(a·b)·(c·d) = (a·c)·(b·d)` を満たす
- これらを**直接証明**することも可能（→ Ch1 で加法版・乗法版は演習）だが、いずれも**可換モノイドの一般的性質**から導ける
- そこで本章の方法: 可換モノイドという代数構造を定義 → その基本性質（交換則）を 1 回証明 → Nat の加法と乗法がいずれも可換モノイドだと示す → そこから導く
- そのために必要な Lean の機能（`structure`・構造を引数に取る一般化された証明・`class`）も紹介する

## 2.1 型は集合、構造はデータ

- Ch1 では型は「命題」だった。ここでは型は「住人を持つ集合（carrier）」の顔
- 「集合とその上の構造」をデータとして与える: 演算と「それが法則（結合律・単位律・逆元…）を満たす証明」を 1 つの項に束ねる——**Ch1 の `⟨h.2, h.1⟩` ペアの大きい版**。`structure` キーワードでこういうレコード型を作れる
- 「性質として**述べる**」か「**構造（データ）**とする」か。普段あまり区別しないが、本書はデータにする（`∃` 主張ではなく演算そのものを項として持つ）。⚠ 深い理由（`∃` だと取り出しに choose が要り監査に古典性が混入）は予告だけ・本格は Ch3／sup
- 署名の読み方（`∀`・`→`・暗黙引数 `{}`）は、構造のフィールドを読むのに要る分だけここで

## 2.2 「α 上の構造」は型・住人が構造ひとつ（ANCHOR `structure_as_data`）

- `#check (Add Nat)` → `Add Nat : Type`。`Add α` の住人は「α 上の二項演算ひとつ」——`Add α` は二項演算を 1 つ持つ**1 フィールドのレコード**で、関数型 `α→α→α`（＝`Map(α×α, α)`）と**同型と思える**（＝ではない・精度①）
- `#check Add` → `Add` は「型に型を返す」（`Type → Type` と読み下す・universe `.{u}` は Ch3）。「X に X 上の演算構造の型を対応させる写像」
- `example : Add Nat := ⟨Nat.add⟩` と `⟨fun a b => a*b⟩`——**乗法すら住人になれる**。Add は法則を持たないから。同じ集合 Nat に構造は複数載る
- **なぜ Add と Mul を分けるか**: `Mul α` も集合としては同じ（二項演算 1 つ）。分ける理由は ① 記法 `+`/`*` を区別するため ② 環のように**二演算を同時に持つ**ため（「加法／乗法」という呼び名は気持ちの問題・型として区別したいだけ）
- 法則は構造の側（次節）が束ねる

## 2.2b Nat が標準ライブラリで持つ構造たち（ANCHOR `nat_structures`）

- mathlib なしの core でも、Nat には演算子クラスが付いている: **二項演算付き集合** `Add`/`Mul`（`a+b`・`a*b`）・**点付き集合** `Zero`/`One`（指定された住人 0・1）・**二項関係付き集合** `LE`/`LT`（`a≤b`・`a<b`）・引き算 `Sub`
- `#check (Mul Nat)`・`#check (Zero Nat)`… いずれも `Type`——§2.2 の `Add Nat` と同じ「構造＝データ」。住人は演算/点/関係ひとつ
- **名前は notation と対応**: `Add`→`+`・`Mul`→`*`・`Zero`→`0`・`One`→`1`・`LE`→`≤`・`LT`→`<`。クラス名が記法の担い手（§2.4 の局所記法・Ch3 の `class` 解決へ繋ぐ）
- ⚠ ただし **法則（結合律・可換律…）はまだ無い**——`Add Nat` は二項演算 1 つだけ。法則を束ねるのが次節の `CommMonoidStr`、法則を被せた階層（モノイド〜体〜順序）は Ch3

## 2.3 一般構造で 1 回証明する（ANCHOR `general_proof`）

- **構造の上に構造を重ねられる・性質も構造（フィールド）と思う**: 二項演算付き集合 → 結合的二項演算付き集合 → 可換モノイド…と法則を足していく（`extends` の予告・Ch3 の階層へ）
- `structure CommMonoidStr (α) where op; op_assoc; op_comm`（演算＋法則の証明を束ねる）
- 交換則 `(a⋆b)⋆(c⋆d) = (a⋆c)⋆(b⋆d)` を結合律＋可換律**だけ**から証明（公理ではない・**Ch1 の `nat_interchange` の抽象版**）。calc は Ch1 既出なので証明がそのまま読める（term mode・`by` は Ch6）
- **具体→抽象の回収**: Ch1 で `Nat.add` について直接証明した式を、ここでは構造の言葉で 1 回証明
- `natAdd`・`natMul`（Nat の 2 つの可換モノイド・法則は core の定理を渡すだけ）→ 1 回の証明が `+` と `*` の両方に効く（`interchange natAdd …` が具体形に defeq 一致）。**乗法版を直接書く労力（Ch1 演習）が、ここで無料になる**
- **抽象化の威力**: structure を引数に渡すだけ——instance も class もまだ要らない

## 2.4 記法は付けられるか？（ANCHOR `local_notation`・L39 の回収）

- 「`op` に notation を付けられる？ structure じゃなくて class じゃないとダメ？」への答え
- 固定した構造 `natAdd` には**局所記法 `⋆` を当てられる**（structure のままで可能・`interchange natAdd` がそのまま使える）
- だが `⋆` は「natAdd という特定の構造」に固定。型ごとに構造を自動で選ぶ**多相な `+`**（ℝ でも Nat でも `a+b`）は作れない——構造を探す仕組みが要る → 次節 class

## 2.5 class＝自動で見つかる構造（最小導入）

- `M.op a b`／固定記法は煩雑。ℝ では `a + b` と書きたい→それを叶えるのが `class`／`instance`＝「構造を Lean が自動で探して渡す」仕組み。だから次章 ℝ の公理は `class` で書く
- ⚠ ここは**最小限**: 「class = 自動で見つかる structure」だけ。解決の深い機構・`(2:Real)` エラー・ダイヤモンド事件は後章（Ch3 で軽く観察、深い話と diamond は Ch8）

## 2.6 種明かし: `⟨⟩` も structure だった（ANCHOR `and_is_structure`）

- `#print And` → And は structure。Ch1 で使った `⟨h.2, h.1⟩` の `⟨⟩` の正体（Ch4 帰納型・Ch5 Partition へ繋ぐ）

## 🪟 理論の窓候補: bundled と unbundled

- 本書の `CommMonoidStr (α : Type)` は **unbundled**（台集合 α はパラメータ・構造は α の上のデータ）
- **bundled** 版は台集合もフィールドにする定義（`structure Monoid where carrier : Type; op : carrier→carrier→carrier; …`）——群の圏の対象などに使う。mathlib も代数は unbundled・圏論的対象は bundled と使い分ける
- 本線には入れず、ここで対比だけ（深掘りは発展）
