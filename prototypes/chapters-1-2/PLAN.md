## 第1章に対する具体的な指示

- 項 `e` から一つの項 `fun x => e` を作る、という説明を加える。
- `x` は引数の名前であり、任意の項を入れる場所ではない。名前を変更するときは本体の対応する名前も変える。
- `e` では引数 `x` を使える。
- `fun` と `=>` 自体は項ではなく、関数の項を作るための特別な記号だと注意書きする。
- 多変数関数のバインダー形式では、3引数以上の説明を練習の前へ移す。
- 抽象的な命題族を用いた第2章への導入を、具体的な証明につながる説明にする。

## 第2章に対する具体的な指示

採用する数学の題材は次の四つ。

1. 単射の合成は単射 — 本文の中心。
2. 単射による左キャンセル — 本文は各点での等式。関数の等号による述べ直しは追加の話題。
3. 単調写像の合成は単調 — `Nat → Nat` の写像で扱う練習。
4. 左逆を持つ写像は単射。

既存の抽象的な例1・例2と練習28〜31は取りやめる。他の抽象的な命題変数の例も具体例に置き換える。
番号は新しい順序で振り直すため、試作の「練習28」などは元の同番号の問題とは別の内容である。

最初に単射性の具体例を置き、証明を考えるときにどう頭を使うかを説明する。
結論から必要な対象・仮定を決め、欲しい結論を返す仮定を探し、適用を組み合わせる。
その後、できた項を内側から読んで型を検査する。

- `rfl` の基本的な説明は本文に残す。
- **不等式（≤など）の定義と証明の内部を、帰納型を扱うところへ回す。**
  音声入力の「フト式」について、ユーザーが「不等式」と明確化した。
- 単調写像の合成では、単調性を仮定し、その証明を適用するだけにする。
- 抽象的な命題の一般論と例を別々の節に分けず、具体例を説明した場所で対応を整理する。

## プレビュー後の追加指示と反映（2026-09-27）

### 第1章

- 適用を見分ける「項の後にスペースを挟んで項が続く」という説明を、最初の適用の説明へ移す。
- 型の決まり方は、適用の型を内側から求める手順と、期待される型から引数・本体へ情報を伝える手順を詳しく説明する。
- 依存関数は Fin の族から項を選ぶ例を先にする。Fin 0 に項がないため、全自然数を入力にする例は Fin (n + 1) / Fin (n + 2) を使う。
- 最初の番号0、最後の番号 n、番号1を選ぶ三例を置き、入力によって結果の型が変わることを #check と #eval で読む。
- idAt は Fin の例の後に置く。Tuple / constTuple は章末問題の準備に移し、本文の中心から外す。
- 暗黙引数は、型引数自体が消えるわけではないこと、明示引数の型から補うこと、期待される型から補うこと、手がかりが不足する場合を順に説明する。
- 暗黙引数を明示する `(α := Nat)` と `@idImplicit Nat 3` も説明する。

### 第2章

冒頭の見方 → 単射の合成（証明の組み立てと型検査を本文で説明、練習28は単調写像の合成）→ 左キャンセル（本文は点ごとの等式）→ Eq と rfl・等号の三つの道具 → 左逆 → 現在の型検査の整理 → 旧版の型検査の節（比較用）→ 章末問題（練習35に Map 間の写像の単射性のLean形式化）。

- 冒頭では「証明・保証を与えられたか」に注目する。「ならば」の保証は保証から保証を作る関数、全称命題の保証は対象ごとに保証を返す依存関数、と説明する。
- 述語を「対象ごとに命題を割り当てるもの」と説明し、命題を型と見ると述語は型の族になることを、冒頭に短く追記する。全称命題の証明はその各型の項を返す依存関数であり、依存積の項に対応する。
- この読み替えに人間が納得することと、書いた項の型を機械が検査することを区別する。機械が任意の命題の真偽や証明の有無を判定するとは説明しない。
- 今回ユーザーが指定した P・Q・P(x) は冒頭の概念説明にだけ使う。抽象的な `P Q : Prop` の Lean 例・練習には戻さない。
- 単射の合成はまず普通の数学の証明を書き、学生のレポートを採点する目線で読む。受け取る対象と仮定、仮定への適用へ分解する。
- `hf`、`hg`、`h` は仮定を保証する証明書の名前である、と説明する。
- 適用の型を答える旧本文練習を、機械の型検査を追う本文へ変更する。単射の合成の証明を組み立てる手順も、練習ではなく本文で説明する。
- 左キャンセルの本文は `∀ t, …` の形にする。`congrFun` と `funext` は不要なので、この説明と実装を外す。関数の等式・誘導写像の単射性は章末でLeanによる形式化を問う。数学的な主張は問題文で述べ、`congrArg` と `funext` の使い方をヒントにする。
- 左逆の前に Eq / Eq.refl / rfl を説明する。Eq の帰納型としての定義と等号の道具の構成は後へ回す。
- 左逆も数学の証明から始める。`Eq.symm`、`Eq.trans`、`congrArg` は Eq の節で先に説明し、左逆の節では具体的な等号の列への適用を示す。

## Eq の説明と旧版比較の追加（2026-09-27）

- `rfl` は `Eq.refl` の対象を暗黙引数にした `def` であると説明する。計算による型の照合は `Eq.refl` を直接使っても働く。
- Eq の節で、左逆より先に `Eq.symm`・`Eq.trans`・`congrArg` の型と使い方を説明する。
- 集合の言葉では、反射性を満たす最小の二項関係が対角集合であることから、対称性・推移性を理解できる。同じ関数による像も対角上にあるので、congrArg の性質も説明できる。
- この最小性は数学的なイメージと明記し、Lean では帰納型の原理を使うと説明する。任意の反射的関係が対称的・推移的だとは説明しない。具体的な帰納型の証明コードは次の章以降へ回す。
- 単調性の説明、合成について証明すべき事実、証明を書く課題を練習29にまとめる。単独の節は作らない。
- 左キャンセルの補足を、Map 間の写像の単射性へ述べ直す練習30に変更する。Lean の関数外延性の実装はまだ要求しない。
- 旧6節「型を追うことが、証明を確かめることになる」は本文を変更せず残す（節番号のみ5へ）。直後に旧版の「型検査が証明の検査になる」を比較用の6節として追加する。
- 旧版の本文・例・但し書きは省略しない。以前の `modus_ponens` を読み込むための新しい例は加えず、当時の `#print` コマンドと出力を引用として表示する。
- コピー元の節そのものは `comparison/02_Forall-type-checking-original.txt` に保存。節本文が維持されていることは `checks/checking-comparison.json` に記録する。

説明の照合には、使用中のLean 4.30.0の `Init/Prelude.lean` と、[公式資料の帰納型の説明](https://lean-lang.org/theorem_proving_in_lean4/Inductive-Types/)を用いた。`Eq.symm`・`Eq.trans`・`congrArg` が追加の公理に依存しないこと、および `Eq.refl` の場合分けで同じ性質を証明できることもLeanで確認した。
