はじめての Lean

型と項 I — 関数と依存関数型

Lean が証明を検査する仕組みを知るために、まずコードの読み方から始めよう。この章では、数や関数を例に、書かれた項がどんな型を持つかを一つずつ確かめる。その読み方を、次の章で証明に当てはめていく。

この教材の読み方

中心は、書かれたコードを解読することである。項を見るたびに型を予想し、 #check の出力で確かめよう。各節の練習には、予想を言葉にする問題と、小さな項を書いて確かめる問題がある。本文にはその場で確認したい問題を置き、短い確認問題は本文の説明に続けて置き、組み合わせの練習や発展問題は章末に集めた。型を追う手順をつかむことが目的である。型検査がそのまま証明の検査になることを、次の章で経験する。

1. 項と型

Lean に書くものの基本の単位を項（term）と呼ぶ。項とは何かの正確な定義はここでは与えないが、さしあたり #check の右側に書いてエラーが出ないものは項だと考えてよい。

型（type）は、ひとまず集合のようなもの、その型の項は要素のようなものと思ってもよい。ただし、これは大まかなイメージであり、型や項には、それらを作り、扱うための規則がある。以後、その規則を少しずつ見ていく。

#check e は、項 e の型を調べて表示するコマンドである。ここで、調べる対象の e は項だが、#check e 全体は項ではなく、Lean に対する指示である。後で使う def も、新しい定義を導入するコマンドであり、項とは区別する。エディタ右側のパネル（Infoview）に表示される結果を、本文では独立した枠で示す。実際に Lean を書くときも、Infoview の表示や項にマウスを重ねたときの型表示を使い、どのような型として読まれているか、どこで型が合わなくなったかを確かめながら進める。

#check 3
3 : Nat

これは「項 3 は型 Nat（自然数の型）を持つ」と読む。数学の $3 \in \mathbb{N}$ のようなものと思ってよいが、厳密には異なり、 : は項の型を示す記号であって、集合への所属を表す ∈ とは区別する。

#check true
Bool.true : Bool

「項 true は型 Bool（真偽値の型）を持つ」。表示が Bool.true となっているのは、これが正式な名前だからである。ここで . は名前の区切りで、接頭辞 Bool と名前 true をつないでいる。Lean はこの区切りを使って名前を扱う。標準ライブラリでは true という短い名前も用意されているので、どちらでも書ける（名前の詳しい仕組みは05_MathematicalTools.lean 7節で見る）。

すべての項は型を持つ。ここで大事な観察が1つある。 型を表す表記それ自体もまた項である。実際、Nat を #check の右に書くと:

#check Nat
Nat : Type

Nat という表記は、Type という型を持つ項なのである（以下ではこのことを、少し縮めて「型も項である」と言う）。

では Type は？

#check Type
Type : Type 1

Type もまた項であり、その型は Type 1。

型が項と同じ資格を持つ、というこの一様性が Lean の設計の核で、これがあるから「型を受け取る関数」「型を返す関数」が書ける（3節の Map と4節）。

数の演算や、等式も項として書ける。それぞれにどんな型が付くかを見てみよう。

#check 3 + 4
3 + 4 : Nat

「3 + 4 という項は Nat 型を持つ」と読む。

#check 1 + 1 = 2
1 + 1 = 2 : Prop

今度は、出力の型が Nat ではなく Prop になった。別の例も見てみよう。

#check 2 = 1
2 = 1 : Prop

こちらも型は Prop である。ここで現れた Prop は、命題たちの型である。等式 1 + 1 = 2 も 2 = 1 も命題なので、Prop 型の項になる。 2 = 1 のような偽の命題も、命題としては立派な項であることに注意しよう。 #check は命題の真偽を判定しているわけではない（証明の話は 02_Forall.lean で扱う）。

ここまでで確かめたことは2つである: 項の型はいつでも #check で調べられること、そして型も項であること。

#check という機能があることから分かるように、Lean には項を与えると、その型を機械的に計算する仕組みがある。この仕組みを証明の検証に使うのが、冒頭で述べたこの教材の行き先である。例えば 1 + 1 = 2 という命題そのものを型として、その型の項を作ることが、この等式の証明を与えることになる。その項が指定された型を持つかを検査すれば、証明の検査になる。この対応を、次の章では単射の合成などの具体例で読む。まずこの章で関数の型を追い、次の 02_Forall.lean で証明の例を読む。

2. def — 新しい項を定義する

def 名前 : 型 := 項

と書くと、項に新しい名前を付けて定義できる。:= の右辺には、すでに使える項や、それらを組み合わせた項を書く。定義した後は、左辺の名前自体を項として使える。 def 全体は、定義を導入するコマンドである。この形の宣言には、終わりを示す特別な記号はいらない。 Lean は構文に従って右辺の一つの項を読み取るので、改行しただけで宣言が終わるわけではない。

def x : Nat := 2
#check x
x : Nat

「x という Nat 型の項を、2 として定義した」と読む。型は注釈どおり Nat。名前 x 自体が値を決めるのではなく、右辺の 2 が定義の中身を決めている。

定義した項は、それ自体また項として使える:

def y : Nat := x

#check y
y : Nat

項を扱うコマンドをあと2つ紹介する。#eval は項を計算して値を表示する:

#eval x
2

#print は、名前に付けられた定義そのものを表示する:

#print x
def x : Nat :=
2

さて、ここからがこの教材の最重要のテーマである。 Lean は def の宣言を受理する前に、型検査を行う。 := の右の項が、コロンの右に指定した型を持つかを確かめる。指定した型も手がかりとして使い、一致しなければ宣言を受理しない。

この教材では、項 M と型 A が与えられ、M : A が成り立つかを確かめることを型検査という。項だけからその型を求めるのが型の計算で、 #check はこれを行う。読者がその計算を自分の手でなぞるのを推測と呼ぶ。 def 名前 : 型 := 項 は、Lean に 項 : 型 の型検査を依頼する形である。

読む側の目線で言えば、次の定義の右辺には Nat 型の項を期待する:

def bad : Nat := true
error: Type mismatch
  true
has type
  Bool
but is expected to have type
  Nat

#check true と同じく、true の型は Bool。 Infoview は、要求された Nat と合わないと報告している。

コメントと docstring

ソースには、Lean が読み飛ばすコメントを書き込める。

def x : Nat := 2   -- `--` から行末まではコメント

/- 複数行にわたる
   コメントはこう書く -/

この教材の地の文が入っている /-! … -/ も、コメントの一種である。

もう1つ、宣言の直前に /-- … -/ と書くと、docstring（その宣言の説明書き）になる:

/-- 最初に定義した数。 -/
def x : Nat := 2

docstring は直後の宣言に結び付けられ、エディタで名前にカーソルを乗せると、型と一緒にこの説明がポップアップで表示される。以後のコードにも、 -- のコメントや docstring で説明を添えていく。

3. 関数

集合 $A$・$B$ に対して写像全体の集合 $\mathrm{Map}(A, B)$ が定まるのと同様に、型 A・B に対して「A から B への関数の型」A → B が定まる。つまり矢印 → は、2つの型から新しい型を1つ作る操作を表す記号であって、それ自体が具体的な関数を定めるのではない。ただし集合の場合と違い、A → B は写像概念から定義されたものではない——関数型は、これ以上さかのぼれない原始的な部品である。

記号の入力のしかた

VS Code の Lean 4 拡張では、\to の後に空白か Tab を押すと → を入力できる。他の記号も \ から始まる略記で入力する。記号にマウスを乗せると打ち方を確認できる。以後も初出時に打ち方を添え、一覧を 03_InductiveTypes.lean の付録に置く。

fun 記法 — 関数を項として書く

関数そのものを書くには、fun という記法を使える。引数 x が使えるものとして項 e を書くと、そこから一つの項 fun x => e を作れる。これは「x を受け取って e を返す関数」を表す。 => の右側の項 e を、関数の本体（body）と呼ぶ。

例えば、x : Nat を使って書いた項 x + x から、関数の項 fun x => x + x を作る。本体には、受け取った x を使える。

注意 — 名前を書く場所と、項を書く場所。 この形の x は引数の名前を書く場所であり、任意の項を入れる場所ではない。名前は n などに変えてよく、その場合は本体でその引数を指す名前も揃える。fun x => x + x と fun n => n + n は同じ関数を表す。一方、e の場所には、その引数を使って組み立てた項を書く。

注意 — 記法を作る記号。 fun と => は、それ自体が項なのではない。これらは、引数の名前と本体を組み合わせて関数の項を作るための特別な記号である。全体の fun x => e が一つの項になる。

この教材の表示設定では、出力中の => が ↦ と表示される。同じ関数の書き方である。入力するときも fun x ↦ e と書いてよい。なお、=> は fun 専用ではなく、後で扱う match の分岐にも使う。

この項の型は、次のように読む。引数に型を注釈して fun (x : A) => e と書けば、 x の型はその注釈から A と分かる。注釈を省略した場合も、関数全体に期待されている型から分かることがある。次に、x : A を前提として本体 e の型を調べる。そのもとで e : B ならば、fun x => e は関数型 A → B の項になる。

def double : Nat → Nat := fun n => n + n

#check double
double : Nat → Nat

表示された型は、注釈した Nat → Nat と一致している。定義域の Nat が外側から伝わるので、型を書かなかった引数も n : Nat と決まる。 fun (n : Nat) => n + n と書いたのと同じである。この n は関数の本体で使える仮引数であり、この定義によって外側にも名前 n が導入されるわけではない。

本体の + は、ここでは自然数の足し算を表す記法である。次に、n : Nat を前提として、本体 n + n の型が Nat になるかを検査する。これが通るので、fun n => n + n は注釈どおり Nat → Nat 型の項になる。 2節と同じく、この照合を経て def が受理される。

一致しなければ、もちろん受理されない。本体を true にしてみる:

def bad2 : Nat → Nat := fun n => true
error: Type mismatch
  true
has type
  Bool
but is expected to have type
  Nat

「本体 true の型 Bool が、注釈から要求される行き先の型 Nat と一致しない」という報告である。

一方、行き先を Bool にすれば受理される。これは自然数を受け取り、常に true を返す関数である。引数を受け取っても、本体でその名前を使う必要はない。その場合、引数の名前の代わりに _ と書ける。

#check ((fun _ => true) : Nat → Bool)
fun x ↦ true : Nat → Bool

括弧で囲んだ fun _ => true 全体に、型 Nat → Bool を注釈している。表示では、名前を付けなかった引数に x という名前が補われている。

適用の書き方

数学ではふつう f(x) と書く関数適用を、Lean では f x と、関数と引数を半角スペースで区切って書く。半角スペース自体は演算ではなく項を区切るもので、項を並べる構文が関数適用を表す。読むときも、関数を表す項のあとにスペースを挟んで引数の項が続いたら、 関数適用と読む。double 21 なら、double に21を渡している。項を書く場所で、関数を表す項のあとに引数の項をこのように並べると、関数適用として読まれる。例えば double 21 である。数学で「$f(x)$」と書くとき、私たちは $f$ が関数で $x$ がその定義域の元であることを前提している。Lean の f x も同じ約束の記法で、 f が関数型を持ち、x がその定義域の型を持つことを要求する。

実際 double 21 と書くと、Lean は2つのことを確かめる:

  1. double の型は Nat → Nat（関数型である）——定義域は Nat
  2. 21 の型は Nat——定義域と一致する

この2点が通るから double 21 は合法な書き方であり、項 double 21 の型は矢印の右側の Nat になる。この確認こそが、型検査という機能の中身である。一方、double true は true : Bool が定義域 Nat と合わないので、型エラーになる。

#check double 21
double 21 : Nat

型が分かったところで、値も予想してから計算してみよう。21 + 21 なので 42 のはずだ:

#eval double 21
42

一方、double true を調べると、引数の型が合わずエラーになる:

#check double true
error: Application type mismatch: The argument
  true
has type
  Bool
but is expected to have type
  Nat
in the application
  double true

表示の読み方: binder 形式

宣言には、引数を左に書く記法もある。次は上の double と同じものである:

def double' (n : Nat) : Nat := n + n

#check double'
double' (n : Nat) : Nat

表示が double' (n : Nat) : Nat となったことに注意。これは「引数の列をコロンの左に並べ、最後に結果の型を書く」binder 形式の表示で、#check が関数を表示するときの標準の形である。

double  : Nat → Nat            （矢印形式）
double' (n : Nat) : Nat        （binder 形式）

この2つは同じ型の2通りの表示である。宣言も def double : Nat → Nat := fun n => … と def double' (n : Nat) : Nat := … の2通りに書ける。 binder 形式の宣言は、引数を fun で受け取る形の略記である。上の double と double' は、どちらも定義を展開すると fun n => n + n になり、一致するので同じ項として扱われる。以後どちらの表示も出てくるので、読み替えられるようにしておくこと。

多変数関数はカリー化で表す

まず、ふつうの数学の話から始めよう。集合 $X$・$Y$・$Z$ に対して、写像全体の集合には次の自然な1対1対応がある:

$$\mathrm{Map}(X \times Y, Z) \cong \mathrm{Map}(X, \mathrm{Map}(Y, Z))$$

左辺の写像 $f$ に、$x$ を固定して得られる写像「$y \mapsto f(x, y)$」を対応させる。つまり $x \mapsto (y \mapsto f(x, y))$ という右辺の写像にする。この操作をカリー化（currying）、逆に右辺の写像 $g$ から $(x, y) \mapsto g(x)(y)$ を作る操作をアンカリー化（uncurrying）と呼ぶ。

Lean では、多変数関数も1引数関数を重ねて表す。 2引数なら、1つ目を受け取って残り1引数の関数を返す。例えば、数学でいう写像 $\mathbb{N} \times \mathbb{N} \to \mathbb{N}$、$(a, b) \mapsto a + b$ をカリー化したものを、 plus : Nat → Nat → Nat として定義してみよう:

def plus : Nat → Nat → Nat := fun a => fun b => a + b

読み方の約束を先に押さえる。→ は右結合である:

Nat → Nat → Nat　は　Nat → (Nat → Nat)　のこと

（「Nat を受け取って、関数 Nat → Nat を返す」）。

逆に、適用は左結合:

plus 3 4　は　(plus 3) 4　のこと

（まず plus 3 で関数を作り、それに 4 を渡す）。この2つの約束がかみ合っているおかげで、カリー化された関数を括弧なしで自然に読み書きできる。

括弧を左側に付けた (Nat → Nat) → Nat はまったく別の型 （関数を受け取る関数）になることに注意。括弧は読み方が変わらない場合には省略でき、逆に確認のために補ってもよい。

plus 自体の型は注釈のとおり:

#check plus
plus : Nat → Nat → Nat

では、plus 3 の型は何か。表示を見る前に推測しよう。 plus の型を右結合で読めば Nat → (Nat → Nat)——定義域は Nat、行き先は Nat → Nat。そこに 3 : Nat を渡すのだから、適用の2点確認より plus 3 : Nat → Nat のはずである:

#check plus 3
plus 3 : Nat → Nat

推測どおり。「1つ渡すと、残り1引数の関数が返る」ことが型にそのまま現れている。

もう1つ渡せば Nat になるはずで:

#check plus 3 4
plus 3 4 : Nat
#eval plus 3 4
7

多変数関数の binder 形式

1変数のときと同じく、引数を宣言の左側に並べられる。例えば plus は次のようにも定義できる（同じ名前を重ねて定義せず、いずれか1つを使う）:

def plus (a : Nat) (b : Nat) : Nat := a + b

同じ型の引数は、まとめて (a b : Nat) と書いてもよい:

def plus (a b : Nat) : Nat := a + b

fun の引数もまとめられる。fun a b => a + b は、 fun a => fun b => a + b の略記である。まず a を受け取り、「b を受け取って a + b を返す関数」を返している。したがって、もとの定義は次のようにも書ける:

def plus : Nat → Nat → Nat := fun a b => a + b

3引数以上も同じことの繰り返し。 Nat → Nat → Nat → Nat は Nat → (Nat → (Nat → Nat)) と読む。

def addMul (a b c : Nat) : Nat := a + b * c

#check addMul
addMul (a b c : Nat) : Nat

これは Nat 型の引数を3つ受け取って Nat 型の項を返す、という binder 形式の表示である。矢印形式では addMul : Nat → Nat → Nat → Nat と読める。

型はどう決まるか——下から計算し、上から期待を伝える

ここまで、項を見るたびに型を確かめてきた。その手順を整理しよう。まず、すでに名前の付いている double や plus の型は、宣言から分かる。次に、それらを使って作った大きな項の型を、部分項の型から順に求める。

目で追うときは、まず結合規則に従って括弧を補い、どこまでが一つの項かを確認する。次に、いちばん外側の適用を関数側と引数側に分け、それぞれがさらに適用なら同じように分ける。こうして小さな項まで分けたら、その型を手がかりに、適用の型を順に求めて全体へ戻る。ただし、引数の型を省略した fun などでは、外側に書かれた型注釈も先に使う。この二つの向きを、以下の例で確かめよう。

適用の型を、内側から求める

適用 f a を読んだら、関数の側 f と引数の側 a に分ける。 f の型が A → B で、a の型が A と一致すれば、結果の型は B になる。関数の定義の中身を実行するのではなく、まず入力と出力の型を読んでいる。

f : A → Ba : A
f a : B

ここで A や B が関数型でも、規則は変わらない。 applyTo21 double なら入力型 A は Nat → Nat、結果の型 B は Nat。一方、plus 3 では入力型が Nat、結果の型が Nat → Nat である。

複合した項を、小さい照合に分ける

例えば double (plus 3 4) を見たら、いちばん外側は double の適用である。その引数 plus 3 4 が Nat 型であることを確かめたい。そこで、引数の内側に入り、適用を一つずつ読む。

括弧を補うと double ((plus 3) 4) となり、その分解は次の木で表せる。

double ((plus 3) 4)
├── double
└── (plus 3) 4
    ├── plus 3
    │   ├── plus
    │   └── 3
    └── 4

枝分かれしている箇所は一つの関数適用で、上の枝が関数、下の枝が引数を表す。木の末端にある名前や数の型から始めて、それらを組み合わせた項の型を順に求める。

  1. 3 : Nat、4 : Nat。
  2. plus : Nat → (Nat → Nat) なので、plus 3 : Nat → Nat。
  3. その関数に 4 : Nat を渡すので、(plus 3) 4 : Nat。
  4. double : Nat → Nat にこの Nat 型の項を渡すので、全体も Nat 型。

このように、部分項の型を調べ、入力型が合うかを照合し、結果の型を得る。同じ手順を繰り返すだけで、大きな項の型も確かめられる。

#check double (plus 3 4)
double (plus 3 4) : Nat

これは型の確認である。値が14になることを計算する操作は #eval が担当する。型を求めるために 3 + 4 やその2倍を計算したわけではない。

期待される型から、関数の本体へ

逆向きの情報も使える。次の宣言では、右辺全体に Nat → Nat という型を期待する。

def double : Nat → Nat := fun n => n + n

期待される型の入力側が Nat なので、受け取る n の型は Nat と決まる。出力側も Nat なので、次には本体 n + n が Nat 型になるかを確かめればよい。 関数全体に求める型から、引数の型と本体に求める型を取り出している。

ここからは、n : Nat を使って本体の型を調べる。自然数の足し算は Nat を二つ受け取って Nat を返すので、n + n : Nat が得られる。要求されていた出力型と一致したから、fun n => n + n 全体が Nat → Nat 型と確かめられる。

本体を true に変えると、ここで得られる型は Bool になる。要求された Nat と一致しないため、先ほど見た型エラーになる。「どこでどの型が要求され、実際の型が何だったか」を追うと、エラーの意味も読める。

型注釈が、項の読み方を決める

数字も、期待される型を手がかりに読む。型の指定がなければ 2 は自然数として読まれるが、 Int（整数の型）を指定すれば、整数の項として読まれる。

#check 2
2 : Nat
#check (2 : Int)
2 : Int

期待される型は、項の内側にも伝わる。次の式では、足し算の結果を Int 型と指定しているので、 2 と 3 も整数の項として読まれる。

#check (2 + 3 : Int)
2 + 3 : Int

部分項から型を求めることと、期待される型を部分項へ伝えることが組み合わさって、省略された引数の型や演算の読み方が決まる。このように省略などを補う処理を、後でエラボレーションと呼ぶ。補った後も、できた項が宣言された型を持つかを検査する。

このあとの依存関数や暗黙引数でも、同じ考え方を使う。型を予想するときは、今どの項を見ているか、その項にどの型を期待しているかを分けて追おう。

照合が失敗すれば、その場所がエラーになる。double に関数 plus を渡してみる:

#check double plus
error: Application type mismatch: The argument
  plus
has type
  Nat → Nat → Nat
but is expected to have type
  Nat
in the application
  double plus

「引数の型 Nat → Nat → Nat が、要求される型 Nat と合わない」と、規則が破れた部分項を名指しで教えてくれる。エラーの下にはさらに double sorry : Nat という表示も出る。ここで初めて出てきた sorry は、「この部分は未完成」という印の項で、どんな型の項の代わりにも置ける。長い証明の途中でも、まだ書けていない部分に置いて残りを先に書けるが、その部分を埋めるまでは証明は完成していない。 #check は、エラーになった引数を sorry で置き換えて、残りの部分の型の計算を続けてくれたのである。自分で書くこともできる。例えば

def later : Nat := sorry

は受理されるが、warning: declaration uses `sorry` という警告が出る。未完成のまま進めても、そのことを Lean は見逃さない。

では double plus 3 4 と括弧なしで書いたらどうなるか。適用は左結合なのでこれは ((double plus) 3) 4 と読まれ、最初の double plus の時点で上と同じエラーになる。double (plus 3 4) の括弧は省略できない。

4. 依存関数型 — 入力によって結果の型が変わる

まず集合族で考えよう。集合 $A$ を添字集合とする集合族 $(X_a)_{a \in A}$ に対して、その直積 $\prod_{a \in A} X_a$ の要素は、各 $a$ に $X_a$ の要素を一つずつ指定するものである。これを依存関数と思えばよい。値 $f(a)$ の所属先 $X_a$ が、入力 $a$ に依存している。

族が定数、つまりすべての $X_a$ が同じ集合 $X$ ならば、これは普通の関数 $A \to X$ であり、$\prod_{a \in A} X = \mathrm{Map}(A, X)$ となる。

直和への関数と切断

族が定数でない場合も、直和 $E = \coprod_{a \in A} X_a$ を使えば、普通の関数として表せる。この直和の要素は、添字と要素の組 $(a, x)$（$x \in X_a$）である。

依存関数 $f$ を $s(a) = (a, f(a))$ という関数 $s : A \to E$ に読み替える。射影 $\pi : E \to A$、$\pi(a, x) = a$ に対して、これは$\pi \circ s = \mathrm{id}_A$ を満たす。このような $s$ を $\pi$ の切断（section）と呼ぶ。

逆に、全射 $F : E \to A$ の切断 $s$ を考えてもよい。$F \circ s = \mathrm{id}_A$ という条件は、各 $a$ について $s(a) \in F^{-1}(a)$ という条件である。したがって切断とは、ファイバーを集合族 $(F^{-1}(a))_{a \in A}$ と見たときの依存関数である。

型の族と依存関数

Lean では、B : A → Type が各 a : A に型 B a を割り当てる型の族を表す。この族の各型から項を一つずつ返す関数の型を依存関数型といい、次のように書く:

(a : A) → B a

集合族の直積 $\prod_{a \in A} B(a)$ に対応する型である。族 B の行き先はいつも Type だが、依存関数の結果の型 B a は入力 a に応じて変わる。結果の型が入力に依存しない特別な場合が、これまでの A → C である。

自然数を添字にする型の族 Fin

まず、自然数 $n$ に対して型 Fin n を対応させる例から始めよう。 Fin n は、集合 $\{0,1,\ldots,n-1\}$ に対応する型と思ってよい。例えば Fin 3 には0・1・2、Fin 5 には0・1・2・3・4に対応する項がある。

#check Fin
Fin (n : Nat) : Type

矢印形式で読むと Fin : Nat → Type である。 Fin 自体は、自然数を受け取って型を返す普通の関数で、型の族を与える。次は、その族の各型から、実際に項を選んで返す関数を考えたい。

なぜ Fin (n + 1) を使うのか

Fin 0 には項がない。そのため、すべての自然数 n に対して Fin n の項を選ぶ関数は作れない。ここでは添字を一つずらし、いつも項を持つ Fin (n + 1) の族を使う。 Fin (n + 1) は、0から n までの番号の型である。

したがって、作りたい関数の型は次のようになる。

(n : Nat) → Fin (n + 1)

n を受け取ってから、返すべき項の型が Fin (n + 1) に決まる。例えば2を受け取れば Fin 3、4を受け取れば Fin 5 の項を返す。これが、結果の型が入力に依存するということである。

例1: いつも最初の番号を選ぶ

どの Fin (n + 1) にも、最初の番号0がある。それを選ぶ依存関数を作ってみよう。

def zeroIndex : (n : Nat) → Fin (n + 1) := fun _ => 0

#check zeroIndex
zeroIndex (n : Nat) : Fin (n + 1)

外側の型注釈から、右辺で受け取る引数の型は Nat、返す0の型は Fin (n + 1) と決まる。この0は、ここでは Nat 型ではなく、指定された Fin (n + 1) 型の項として読まれる。数字をその型の項として書ける仕組みは、後で型の定義とともに説明する。

ここでは引数に名前を付けていないが、返す項に求められる型は、その引数の値に応じて変わる。

#check zeroIndex 2
zeroIndex 2 : Fin (2 + 1)
#check zeroIndex 4
zeroIndex 4 : Fin (4 + 1)

Fin (2 + 1) は計算すれば Fin 3、Fin (4 + 1) は Fin 5 である。表示に足し算が残っていても、どの入力を結果の型に代入したかが読み取れる。

#eval zeroIndex 4
0

表示される値はいつも0でも、返される項の型は入力によって異なる。依存しているのは、まず値の所属先となる型である。

例2: 最後の番号を選ぶ

今度は0から n までのうち、最後の番号 n を選ぼう。標準ライブラリの Fin.last は、その番号を Fin (n + 1) 型の項として返す関数である。

#check Fin.last
Fin.last (n : Nat) : Fin (n + 1)

この関数を使えば、次のように書ける。Fin.last がその型の項をどう作るかは、部分型を扱うところで説明する。今は型から入力と出力を読んで使ってみよう。

def lastIndex : (n : Nat) → Fin (n + 1) := fun n => Fin.last n

#check lastIndex 2
lastIndex 2 : Fin (2 + 1)
#eval lastIndex 2
2
#eval lastIndex 4
4

zeroIndex と lastIndex は同じ依存関数型を持つ。しかし、前者は最初の番号、後者は最後の番号を選ぶ。型は各入力での所属先を決めるが、その中のどの項を返すかまで決めるわけではない。

例3: いつも1を選べる族にする

いつも番号1を選びたいなら、少なくとも二つの番号を持つ Fin (n + 2) の族を使えばよい。 n = 0 のときでも、結果の型は Fin 2 になり、番号1を返せる。

def oneIndex : (n : Nat) → Fin (n + 2) := fun _ => 1

#check oneIndex 2
oneIndex 2 : Fin (2 + 2)
#eval oneIndex 2
1

ここまでの三つは、いずれも自然数を受け取って、指定された有限の型の項を一つ返す例である。 Fin は型の族を与える関数、zeroIndex・lastIndex・oneIndex は、その族から項を返す依存関数である。

各集合に恒等写像を割り当てる

次は、受け取る対象を自然数から型に変えてみよう。数学では、各集合 $X$ に恒等写像 $\mathrm{id}_X \in \mathrm{Map}(X,X)$ を対応させる。入力が $X$ なら返す値の所属先は $\mathrm{Map}(X,X)$ なので、これも依存関数と見られる。

Lean では型 α を受け取り、α → α 型の恒等関数を返す。その関数は a : α を受け取って、そのまま a を返せばよい。

def idAt (α : Type) (a : α) : α := a

#check idAt
idAt (α : Type) (a : α) : α

矢印形式では idAt : (α : Type) → α → α と読む。最初に型を一つ渡すと、残りの関数の型が決まる。

#check idAt Nat
idAt Nat : Nat → Nat
#check idAt Bool
idAt Bool : Bool → Bool

idAt Nat と idAt Bool は、異なる型の上の恒等関数である。 zeroIndex では入力に応じて有限の型が変わったが、ここでは返す関数の型が変わる。

#eval idAt Nat 42

42

idAt Nat : Nat → Nat に 42 : Nat を渡している。最初の引数で残りの型が決まり、その型に合う次の引数を渡す、という順序で読める。

依存する適用の規則

f : (a : A) → B a に x : A を渡すと、結果の型は B x になる。入力型が合うことを確かめ、結果の型の中にも、渡した対象を代入する。

f : (a : A) → B ax : A
f x : B x

zeroIndex 2 なら、B n = Fin (n + 1) に2を代入して Fin (2 + 1)。 idAt Nat なら、B α = α → α に Nat を代入して Nat → Nat となる。入力によらず結果の型が同じ場合が、これまでの普通の関数型 A → C である。

✏ 練習

解答 17

#check idAt (Nat → Nat)
idAt (Nat → Nat) : (Nat → Nat) → Nat → Nat

A = Nat → Nat を代入した A → A、つまり (Nat → Nat) → Nat → Nat。右結合の約束で外側の括弧は表示されない。

#eval idAt (Nat → Nat) double 21
42

idAt (Nat → Nat) double は double そのもの。

def constAt (A B : Type) (a : A) : B → A := fun _ => a

#check constAt Nat Bool 5

5

idAt A が恒等関数を返すのに対し、constAt A B a は定数関数を返す。

型引数を補ってもらう — 明示引数と暗黙引数

idAt Nat 3 では、型 Nat と、その型の項 3 を順に渡した。しかし、3 が Nat 型だと分かれば、最初の型引数も Nat と決められる。このように、ほかの型情報から決まる引数を、Lean に補ってもらうことができる。

型引数は、なくなったのではない

同じ恒等関数を、型引数の括弧だけ変えて定義する。

def idImplicit {α : Type} (a : α) : α := a

#check idImplicit
idImplicit {α : Type} (a : α) : α

(a : α) は呼び出す側が通常書く明示引数、{α : Type} は通常省略して補ってもらう暗黙引数である。型と項の二つを受け取る仕組みは変わっていない。呼び出すときに、どちらの引数を書くかが違う。

渡した項の型から補う

idImplicit 3 と書くと、3は明示引数 a に渡される。 a の型は α でなければならず、渡した3の型は Nat なので、Lean は α := Nat と補う。その結果、返す項の型も Nat になる。

#check idImplicit 3
idImplicit 3 : Nat

同様に true : Bool を渡せば、α := Bool と決まる。「省略したらいつも Nat」ということではなく、渡した項の型を手がかりにしている。

#check idImplicit true
idImplicit true : Bool

補う型を、こちらから指定する

暗黙引数も、名前を指定して渡せる。(α := Nat) は「引数 α に Nat を渡す」という書き方である。次の二つは、型引数を省略したか明示したかの違いだけである。

idImplicit 3
idImplicit (α := Nat) 3

また、関数名の前に @ を付けると、暗黙引数も順に書いて適用できる。この例では @idImplicit Nat 3 と書く。idAt Nat 3 と同じ二つの引数が見える。

結果に期待される型から補う

渡す値だけが手がかりではない。次の定義では、右辺に Nat → Nat を期待している。

def natId : Nat → Nat := idImplicit

#check natId
natId : Nat → Nat

型引数を補った後の idImplicit の型は α → α である。これを要求された Nat → Nat と照合すると、α := Nat と決まる。値の引数をまだ渡していなくても、置かれた場所の型から補える例である。

手がかりが足りない場合

一方、型注釈なしに def unknownIdentity := idImplicit とだけ書くと、どの型 α の恒等関数を定義したいのかが決まらず、受理されない。結果の型を注釈するか、idImplicit (α := Nat) のように引数を指定すればよい。暗黙引数とは、型の情報から補えるところを省略する仕組みである。

省略を補う処理をエラボレーションと呼ぶ。補われた引数も含めて完成した項が、要求された型を持つかが検査される。

項を書く場所の _ は、Lean にその部分の補完を求める記号である。一方、fun _ => 0 の _ は、受け取る引数に名前を付けない記号だった。書かれた場所によって役割が違うことに注意しよう。

次の章では、結果の型として具体的な命題を使う。対象ごとに、その対象についての証明を返す依存関数が、全称命題の証明になる。

外側の fun は個数 n を受け取る。作るべき型 Tuple n は Fin n → Nat なので、内側の fun は Fin n の番号を受け取り、自然数7を返す。番号そのものを計算に使わなくても、受け取る番号の型は n によって変わる。
