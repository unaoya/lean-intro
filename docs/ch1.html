証明を読む I — ならばと全称

Intro1a.lean では、関数と依存関数の項について型を追った。この章では、その同じ仕組みが定理の証明の検査になることを確かめる。小さな推論から始め、単射どうしの合成が単射であるという数学の証明まで読む。

命題そのものを型とみなし、その型の項を作ることが証明することである。関数を作る・適用するという既習の操作が、どの証明の手順に対応するかを追っていこう。

0. 証明するとは何をすることか

Intro1a.lean 1節からの積み上げで見たのは、 項の型は機械的に計算・検査できるということだった。このファイルで納得したいのは、次の主張である:

Lean では命題そのものが型であり、その型の項を作ることが、その命題を証明することである。

これが納得できれば、話は一気に進む。証明であるべき項の型を検査して、それが元の命題に一致していれば、証明の正しさを機械的に確かめたことになる——検査の手段は、Intro1a.lean の型検査そのものだからである。ただし、ここで検査されるのは、すでに Lean の命題として書かれた主張に対する証明である。数学の主張をどの定義で、どの命題として表すかは、それとは別に人が考える必要がある。

だがこの主張は、初めて見ると奇妙に響く。証明とは論理をたどる営みで、項とは fun n => n + n のような式だったはずである。なぜ式を作ることが証明になるのか。それを見るために、いちばん小さな推論から一段ずつ始めよう。

命題と証明の書き方

命題は Prop という型を持つ項である。そして P : Prop に対する h : P を、命題 P の証明と読む。

P : Prop    — P は命題
h : P       — h は P の証明

命題を型として持つ項に名前を付けるときは、def と同じ配置で theorem を使う:

theorem 名前 (引数) : 命題 := 証明の項

名前を付けず型と証明の項だけを検査するときは、同じ配置の example : 命題 := 項 を使う。命題を受け取る (P Q : Prop) も、先の引数が後の型に現れる依存関数の引数である。各 a : A に対して Q a が命題であるとき、表示に現れる ∀ a, Q a は、依存関数型 (a : A) → Q a の表記としても読める。その項は、各 a に命題そのものではなく Q a の証明を返す関数である。「すべての a について」という意味は、3節で具体的に見る。

この節の例では、宣言の引数をすべてその場に書く。したがって、まだ section や variable という新しい構文を覚える必要はない。

例1: P と「P ならば Q」から Q

命題 P、Qについて、P であることと「P ならば Q」を仮定する。このとき Q を証明したい。

ふつうの証明。P である。また、P ならば Q である。したがって Q である。∎

型を意識した版。P の証明を hP、「P ならば Q」の証明を hPQ と名付ける:

hP  : P
hPQ : P → Q

hPQ : P → Q は、P の証明を受け取ると Q の証明を返す関数として使える。したがって、hPQ に hP を渡した項 hPQ hP の型は Q である:

hPQ : P → Q    hP : P
----------------------
       hPQ hP : Q

これは f : α → β と a : α から f a : β を得た、Intro1a.lean の関数適用とまったく同じ型の照合である。

theorem modus_ponens
    (P Q : Prop)
    (hP : P)
    (hPQ : P → Q) :
    Q :=
  hPQ hP

#check modus_ponens
modus_ponens (P Q : Prop) (hP : P) (hPQ : P → Q) : Q

宣言の最後で要求されている型は Q、右辺 hPQ hP の型も Q。 Lean が行う検査は、この一致を確かめることである。

✏ 練習

  1. 次の #check の結果を予想してから確かめよ。出力の最後が Q になるまでを、 P → Q の入力型と出力型から説明せよ。
   #check fun (P Q : Prop) (hP : P) (hPQ : P → Q) => hPQ hP
  1. 引数の順だけを入れ替えた theorem use_imp (P Q : Prop) (hPQ : P → Q) (hP : P) : Q の右辺を書け。
解答 1 
#check fun (P Q : Prop) (hP : P) (hPQ : P → Q) => hPQ hP
fun P Q hP hPQ ↦ hPQ hP : ∀ (P Q : Prop), P → (P → Q) → Q

hPQ : P → Q の入力型 P と hP : P が一致するので、適用結果の型は hPQ の出力型 Q になる。

解答 2 
theorem use_imp (P Q : Prop) (hPQ : P → Q) (hP : P) : Q :=
  hPQ hP

引数の順が変わっても、適用する項 hPQ hP は変わらない。

例2: 含意の推移

次は、「P ならば Q」と「Q ならば R」を仮定し、「P ならば R」を証明する。

ふつうの証明。P であると仮定する。P ならば Q なので、Q である。さらに、Q ならば R なので、R である。P を仮定して R を証明したので、 P ならば R である。∎

型を意識した版。「P ならば Q」の証明を hPQ : P → Q、「Q ならば R」の証明を hQR : Q → R とする。目標は P → R である。

  1. P → R を作るため、まず hP : P を受け取る。
  2. 例1と同じ適用により、hPQ hP : Q。
  3. もう一度適用すると、hQR (hPQ hP) : R。
  4. hP : P を受け取って R の証明を返せたので、全体は P → R。

この4段を、そのまま fun と適用で書く:

theorem imp_trans
    (P Q R : Prop)
    (hPQ : P → Q)
    (hQR : Q → R) :
    P → R :=
  fun hP =>
    hQR (hPQ hP)

#check imp_trans
imp_trans (P Q R : Prop) (hPQ : P → Q) (hQR : Q → R) : P → R

項は内側から読めばよい。hPQ hP : Q、したがって hQR (hPQ hP) : R、したがって fun hP => hQR (hPQ hP) : P → R。証明の各文でしていた照合が、そのまま項の型の推測になっている。

✏ 練習

  1. theorem imp_refl (P : Prop) : P → P を書け。
  2. P → Q、Q → R、R → S を順に使う theorem imp_trans3 (P Q R S : Prop) (hPQ : P → Q) (hQR : Q → R)(hRS : R → S) : P → S を書け。まず最も内側の適用の型から予想すること。
解答 1 
theorem imp_refl (P : Prop) : P → P :=
  fun hP => hP

受け取った hP : P をそのまま返すので、関数全体の型は P → P。

解答 2 
theorem imp_trans3
    (P Q R S : Prop)
    (hPQ : P → Q)
    (hQR : Q → R)
    (hRS : R → S) :
    P → S :=
  fun hP => hRS (hQR (hPQ hP))

内側から hPQ hP : Q、hQR (hPQ hP) : R、 hRS (hQR (hPQ hP)) : S と型が決まる。

1. 整理 — 命題・theorem・rfl

0節で使った命題と theorem を整理し、等式の証明 rfl を加える。

Intro1a.lean の1節で見たとおり、命題は Prop という型を持つ項である。等式 1 + 1 = 2 も、不等式 2 < 1 も、その型は Prop である。命題として正しく書けていることと、その命題を証明できることは別である。 2 < 1 のような偽の命題も、命題としては立派な項であり、それを証明するには別に、その命題の型を持つ項が必要になる。

先取り（Intro2）: 記法の仕組みと展開先の違い

=・<・+ は、いずれも記法を関数適用に読み替える仕組みを使う。違うのは、読み替えた先の関数が受け取る引数である。

  • a = b は Eq a b。Eq は両辺の型を暗黙引数として受け取るが、型ごとのインスタンスを必要としない。
  • a < b は LT.lt a b。比較の方法を与えるインスタンスを受け取る。
  • a + b は HAdd.hAdd a b。加算の方法を与えるインスタンスを受け取る。

インスタンスを探して補う仕組みは、Intro2.lean 1節で説明する。ここでは等式や不等式が Prop 型の項であることが分かればよい。 Eq の定義そのものはCH2.lean 8節で見る。

theorem と def

命題も型だから、def と同じ配置で「証明という項に名前を付ける」宣言が書ける。型の位置に命題を、:= の右にその証明を書く。このとき def の代わりに theorem を使う。宣言の形と、右辺の項が指定された型を持つかを検査する仕組みは共通である。

ただし、2つの宣言がまったく同じというわけではない。def で定義した項は型の照合に必要なら定義を展開できるが、theorem の証明の本体は、そのように展開して照合する対象にはならない。

補足（初読は飛ばしてよい）: 同じ命題の証明は区別しない

同じ命題 P : Prop の証明 h₁ : P と h₂ : P は、Lean の型検査では同一視される。これを証明無関連性（proof irrelevance）という。証明の書き方が同じだという意味ではなく、異なる記述であっても、同じ命題の証明として区別しないという意味である。

これは theorem で名前を付けたことによる性質ではない。def で名前を付けた証明でも、仮定として受け取った証明でも同じである。また、証明を作らなくてよいという意味でもない。その命題の証明があることは、型の合う項を与えて別途確かめなければならない。証明をデータとして使う際の制約との関係は、CH2.lean 10節で見る。

theorem one_add_one : 1 + 1 = 2 := rfl

この1行の解剖: one_add_one が名前、1 + 1 = 2 が型（＝命題）、 rfl が項（＝証明）である。def 名前 : 型 := 項 とまったく同じ配置である。

#check one_add_one
one_add_one : 1 + 1 = 2

rfl は、まずは「両辺が定義から計算して一致する」等式の証明と読めばよい。 1 + 1 は計算すると 2 になるので、この等式には rfl が使える。 rfl の一般的な型と、等式の構成子の仕組みは CH2.lean の8節で読む。ここでは、例えば 1 + 1 = 2 と 2 = 2 が計算で一致することを照合すればよい。

✏ 練習

  1. #check 3 < 5 と #check 3 = 5 の表示を予想してから確かめよ（偽の命題も命題である、を思い出すこと）。
  2. theorem two_add_three : 2 + 3 = 5 := rfl を自分で宣言してみよ。
  3. theorem oops : 2 + 2 = 5 := rfl は受理されるか。予想してから試し、エラーメッセージがどの規則の破れを指しているか読み取れ。
解答 1 
#check 3 < 5
3 < 5 : Prop
#check 3 = 5
3 = 5 : Prop

3 = 5 は偽の命題だが、偽の命題も命題——型は同じ Prop である。

解答 2 
theorem two_add_three : 2 + 3 = 5 := rfl

2 + 3 は計算で 5 になるので、rfl が型検査を通る。

解答 3

受理されない。rfl が与える a = a という型を、宣言された型 2 + 2 = 5 と照合しようとしても、2 + 2 と 5 は定義的に等しくないからである。この宣言を実行すると、エラーに次の部分が現れる:

theorem oops : 2 + 2 = 5 := rfl

error: Not a definitional equality: the left-hand side
  2 + 2
is not definitionally equal to the right-hand side
  5

Not a definitional equality は「定義的に等しくない」という意味である。定義的等しさと、等式を別の証明で示せることの違いは、 1節の補足「定義的等しさと、等しいことの証明」で説明した。この例の命題は偽だが、一般に rfl が使えないだけで命題が偽だとは判断できない。補足の 0 + n = n は、rfl では済まなくても証明できる例である。

2. 整理 — 関数型と「ならば」

0節の例1・例2では、含意の証明を関数として使い、また fun で作った。ここでは型の世界の関数と命題の世界の含意を横に並べ、同じ字面になることを整理する。

示すとき。まず数学の言葉では、p を仮定して q を示せば、p → q を示せる。これを証明項の言葉で言い直すと、p の証明を受け取り、q の証明を作る関数を与えることである。 hp : p を仮に置いて hq : q を作れれば、fun hp => hq が p → q の証明になる。型側で、x : α を仮に置いて e : β を作り、fun x => e : α → β を得るのと同じ形である。

使うとき。まず数学の言葉では、p → q と p から q を導ける。これを証明項の言葉で言い直すと、h : p → q と hp : p から、h hp : q を作れるということである。含意の証明を関数として使い、仮定の証明を渡して、結論の証明を作っている。型側で、f : α → β に a : α を渡して f a : β を得るのと同じ適用である。

作るとき（型側）: β の項が1つあれば、α から β への関数が作れる。

def constFun {α β : Type} (b : β) : α → β := fun _ => b

#check constFun
constFun {α β : Type} (b : β) : α → β

示すとき（命題側）: q の証明が1つあれば、p → q が示せる。字面はまったく同じ。

theorem constImp {p q : Prop} (hq : q) : p → q := fun _ => hq

#check constImp
constImp {p q : Prop} (hq : q) : p → q

constFun と見比べてほしい。{α β} が {p q} に変わった以外、引数の並びも結果の形も、そのまま重なっている。

使うとき（型側）: 適用。

def applyFun {α β : Type} (f : α → β) (a : α) : β := f a

#check applyFun
applyFun {α β : Type} (f : α → β) (a : α) : β

読み:「f に a を適用して f a」。

使うとき（命題側）: 適用。これも字面が同じ。

theorem applyImp {p q : Prop} (h : p → q) (hp : p) : q := h hp

#check applyImp
applyImp {p q : Prop} (h : p → q) (hp : p) : q

これも applyFun と同じ形である。読み:「定理（含意の証明 h）に仮定の証明 hp を適用して、結論の証明を得る」——数学の「〜より」の正体である。

-- ここまで型側を `def`、命題側を `theorem` で書いたが、どちらの宣言も
-- 「コロンの右に書いたものを持つ項を、`:=` の右に差し出す」という同じ形をしている。
-- `theorem` と `def` は、指定された型の項を与え、型検査を受けるという点で共通している。
-- 以下のすべての対でも、この形は変わらない。

✏ 練習

型側と命題側を同じ字面で書けることを、自分の手で確かめる。

  1. 「2回適用」を両方の世界で書け: def apply2 {α : Type} : (α → α) → α → α と theorem applyTwice {p : Prop} : (p → p) → p → p。まず fun で引数を受け取る形で書き、次にその引数をコロンの左に移して、 apply2Binder・applyTwiceBinder という名前で binder 形式でも書け。 4つの宣言の型の表示を予想してから #check で確かめよ。表示を矢印形式に読み替えると、書き換えの前後で同じ型になることを説明せよ。
  2. 仮定を受け取る順を入れ替える theorem imp_swap {p q r : Prop} : (p → q → r) → q → p → r を項で書け。 p と q の証明をどの順に受け取っても、適用するときは関数の入力順に戻す。
  3. 同じ字面 fun h => h が、型側の example : Nat → Nat と命題側の example : (1 = 1) → (1 = 1) の両方で通ることを確かめよ。
  4. #check applyFun double 3 の表示を予想してから確かめよ。
解答 1 
def apply2 {α : Type} : (α → α) → α → α := fun f a => f (f a)

theorem applyTwice {p : Prop} : (p → p) → p → p := fun f h => f (f h)

#check apply2
apply2 {α : Type} : (α → α) → α → α
#check applyTwice
applyTwice {p : Prop} : (p → p) → p → p

:= の右は同じ字面。型の世界の「関数を2回適用」と、命題の世界の「推論を2回適用」が、同じ項で書ける。

次に、fun で受け取っていた引数をコロンの左に移し、binder 形式で書く:

def apply2Binder {α : Type} (f : α → α) (a : α) : α := f (f a)

theorem applyTwiceBinder {p : Prop} (f : p → p) (h : p) : p := f (f h)

#check apply2Binder
apply2Binder {α : Type} (f : α → α) (a : α) : α
#check applyTwiceBinder
applyTwiceBinder {p : Prop} (f : p → p) (h : p) : p

最後の2つの引数を矢印形式に読み替えれば、それぞれ (α → α) → α → α と (p → p) → p → p になる。宣言の書き方が変わっただけで、型も、受け取った引数から作る項も変わらない。

解答 2 
theorem imp_swap {p q r : Prop} : (p → q → r) → q → p → r :=
  fun h hq hp => h hp hq

外側では q の証明、次に p の証明を受け取るが、h はまず p、次に q を要求するので、適用は h hp hq の順になる。

解答 3 
example : Nat → Nat := fun h => h

example : (1 = 1) → (1 = 1) := fun h => h

どちらも通る。恒等関数という同じ項が、型の世界でも命題の世界でも働く。

解答 4 
#check applyFun double 3
applyFun double 3 : Nat

f = double（β = Nat）、a = 3 が代入され、結果の型は Nat。

3. 全称と単射の合成

対象の型を A とし、各 x : A に命題を割り当てる関数 Q : A → Prop を考える。このように、対象を受け取ると命題が決まる関数を述語という。「どの x についても Q x」は ∀ x, Q x と書く。これを示すには、x を一つ受け取って Q x の証明を返す。つまり、ここでも作る項は fun である。

小例には等式を使う。a = a のように両辺が同じになる等式の証明は rfl と書く（1節で見たとおりである）。どの自然数も自分自身に等しい:

theorem all_refl : ∀ n : Nat, n = n :=
  fun n => (rfl : n = n)

#check all_refl
all_refl (n : Nat) : n = n

fun n => が「自然数 n を任意に取る」に対応し、その n に対して rfl : n = n を返している。

例3: 単射どうしの合成は単射

写像 f : A → B と g : B → C がともに単射であるとする。 f の単射性を hf、g の単射性を hg と名付け、合成 g∘f : A → C も単射であることを示そう。

ふつうの証明。

  1. x, y を任意に取り、h : g (f x) = g (f y) を仮定する。
  2. 仮定 hg は「どんな u, v についても、g u = g v ならば u = v」という全称文である。u := f x、v := f y と特殊化して h に適用し、f x = f y を得る。
  3. hf を同様に f x = f y に適用して、x = y。これが示すべきことだった。∎

（教科書なら「g (f x) = g (f y) とすると、g の単射性より f x = f y、f の単射性より x = y。∎」と2行で済ませるところである。）

論理式。示すべき結論「合成 g∘f が単射」を、単射の定義まで開くと

∀x ∀y (g(f(x)) = g(f(y)) → x = y)

である。仮定 hg・hf も同じ形の論理式（∀u ∀v (g(u) = g(v) → u = v) など）であることが、この例の主役になる。

形式化を意識した版。論理式で書いたとおり、示すべきは全称と「ならば」の重なった命題である。だから頭の動きは「x, y を取り、さらに仮定 h を取る」。

今度は、仮定 hg・hf の使い方が主役になる。hg 自身が全称+ならばの命題、つまり「当てはめて使う道具」である。全称文・ならば文の使い方は、対象を当てはめて適用すること——例1で hPQ に hP を渡したのと、実は同じ動きである。仮定も既知の定理も、文脈にある部品という資格は変わらない。

項。まず、論理式をそのまま型にして証明する（仮定 hg・hf も単射の定義を開いた論理式の形で書く）:

example {α β γ : Type} {f : α → β} {g : β → γ}
    (hg : ∀ u v, g u = g v → u = v) (hf : ∀ u v, f u = f v → u = v) :
    ∀ x y, g (f x) = g (f y) → x = y :=
  fun x y h => hf x y (hg (f x) (f y) h)

「取る」が3連続の fun x y h——全称も「ならば」も、項では同じ関数である。そして「〜の単射性より」という紙の一語が、適用 hg (f x) (f y) h そのものになる。ふつうの証明で意識した特殊化（u := f x、v := f y）を、ここでは引数として自分の手で書いている。

単射のような頻出の性質には、ライブラリが名前のついた述語を用意している—— Function.Injective f である。直前の全称と含意の式に名前を付けた略記として読める。これで書き直すと:

theorem comp_injective {α β γ : Type} {f : α → β} {g : β → γ}
    (hg : Function.Injective g) (hf : Function.Injective f) :
    Function.Injective (fun x => g (f x)) :=
  fun x y h => hf (hg h : f x = f y)

#check comp_injective
comp_injective {α β γ : Type} {f : α → β} {g : β → γ} (hg : Function.Injective g) (hf : Function.Injective f) :
  Function.Injective fun x ↦ g (f x)

主張が略記で縮んだだけでなく、証明からは特殊化 (f x)・(f y) も消えて hg h だけになった。Function.Injective は点の引数を暗黙引数 （{ } の変種 ⦃ ⦄。ここでは同じものと読んでよい）として宣言しているので、機械が埋めてくれるからである（型注釈 : f x = f y は「f x = f y を得る」という文の写しで、消しても通る）。

✏ 練習

  1. 定義を開いた最初の example で、hg (f x) (f y) h と hf x y (hg (f x) (f y) h) の型を内側から順に予想せよ。
  2. 恒等関数が単射であることを示す theorem id_injective (α : Type) : Function.Injective (fun x : α => x) を書け。
解答 1

h : g (f x) = g (f y) を hg に渡すと hg (f x) (f y) h : f x = f y。それを hf に渡すと hf x y (hg (f x) (f y) h) : x = y となる。

解答 2 
theorem id_injective (α : Type) : Function.Injective (fun x : α => x) :=
  fun x y h => (h : x = y)

恒等関数について仮定される等式は最初から x = y なので、その証明 h をそのまま返せばよい。

4. 整理 — 依存積と「すべての」

3節では ∀ を「任意に取る」「点を当てはめる」と読んだ。ここでは、これが型の世界の依存関数と同じ仕組みであることを整理する。

関数型 α → β を一般化して、行き先の型が入力ごとに変わってよいことにしたのが依存積 (a : α) → P a。P : α → Type は「α の各点に型を割り当てるもの」。

命題側で対応するのは全称量化 ∀ a, Q a。 Q : α → Prop は「α の各点に命題を割り当てるもの」で、形はまったく同じ。

示すとき・使うとき: 関数のときと変わらず fun x => e と f a。 α → β は P が定数のときの特別な場合なので、これは自然なこと。

def mkPi {α : Type} {P : α → Type} (f : (a : α) → P a) : (a : α) → P a := fun a => f a

#check mkPi
mkPi {α : Type} {P : α → Type} (f : (a : α) → P a) (a : α) : P a
theorem mkForall {α : Type} {Q : α → Prop} (h : ∀ a, Q a) : ∀ a, Q a := fun a => h a

#check mkForall
mkForall {α : Type} {Q : α → Prop} (h : ∀ (a : α), Q a) (a : α) : Q a

使うとき（型側）: 点 a を与えると P a の項が出る。

def applyPi {α : Type} {P : α → Type} (f : (a : α) → P a) (a : α) : P a := f a

#check applyPi
applyPi {α : Type} {P : α → Type} (f : (a : α) → P a) (a : α) : P a

使うとき（命題側）: 点 a を与えると Q a の証明が出る。

theorem applyForall {α : Type} {Q : α → Prop} (h : ∀ a, Q a) (a : α) : Q a := h a

#check applyForall
applyForall {α : Type} {Q : α → Prop} (h : ∀ (a : α), Q a) (a : α) : Q a

applyPi と重なる。「一般論に点を代入する」ことの正体が、この適用である。

具体例: 述語と全称命題

Q : α → Prop——命題を返す関数——は、数学でいう述語である。 Intro1a.lean 3節で「型を返す関数」Map を見たのと同じ要領で、具体的に1つ作ってみる:

def IsZero : Nat → Prop := fun n => n = 0

#check IsZero 3
IsZero 3 : Prop

IsZero に点 3 を渡すと、命題 3 = 0 が1つ決まる——n ごとに命題を割り当てる族である。

「すべての n について…」の証明は、依存関数そのものである:各 n を受け取って、命題 IsZero (n * 0) の証明を返す関数を書けばよい。

theorem all_mul_zero : ∀ n : Nat, IsZero (n * 0) := fun _ => rfl

#check all_mul_zero
all_mul_zero (n : Nat) : IsZero (n * 0)

証明が fun _ => rfl で済むのは、IsZero (n * 0) が定義上 n * 0 = 0 で、 n * 0 が計算で 0 になるからである（1節の 1 + 1 = 2 と同じ理屈）。

✏ 練習

  1. #check applyForall all_mul_zero 7 の表示を予想してから確かめよ。引数7を渡すと、結果の命題にも7が入ることを説明せよ。
解答 1 
#check applyForall all_mul_zero 7
applyForall all_mul_zero 7 : IsZero (7 * 0)

∀ n, IsZero (n * 0) に点 7 を代入した、特殊化された命題の証明になる。

5. 型検査が証明の検査になる

含意と全称、単射の合成で行った型の照合から、この章の中心の主張を確かめよう。

証明は項なのだから、「証明が正しいか」は「項が主張どおりの型を持つか」という 型検査の問題になる。型検査は機械的な計算であり、Lean はすべての宣言に対してそれを実行している。だから、ファイルがエラーなしに受理された時点で、そこに書かれた全定理の検査は済んでいる。

ただし2つ、但し書きがある。第一に、この検査は宣言済みの公理に相対的である。 axiom bad : 0 = 1 のような宣言もエラーなく受理できてしまうので、「何を公理として使ったか」は #print axioms で別に監査する必要がある。第二に、証明を保留する印 sorry はエラーではなく警告になる（依存すると #print axioms に sorryAx が現れる）。だから正確には、「エラーがなく、sorry の警告もなく、#print axioms の結果が納得できる公理だけ」を見る。Top.lean の末尾で、主定理に対してこの監査を実行する。

#print axioms modus_ponens
'modus_ponens' does not depend on any axioms

この証明は追加の公理に依存していない。

仮定を取り違えると、型が合わなくなる

含意の推移で、本来 hPQ hP を渡すべきところに hP を直接渡すとどうなるか。

theorem bad_trans (P Q R : Prop) (hPQ : P → Q) (hQR : Q → R) : P → R :=
  fun hP => hQR hP

hQR が要求するのは Q の証明だが、渡した hP は P の証明である。 Lean はこの適用を型の不一致として拒否する。紙の証明で「Q である」という一段を飛ばしたことが、そのまま引数の型の不一致になる。

省略を補う処理と、完成した項の検査

ソースの記法を展開し、暗黙引数などを補うのがエラボレータである。その後、完成した項が宣言どおりの型を持つかをカーネルが検査する。補完の仕組みが賢いことと、出来上がった項が正しいことは、別に確かめられる。詳しい例は CH2.lean の9節で読む。

ここまでで、仮定や対象を受け取り、適用で進む証明を読めた。次は Intro1b.lean で構成子と場合分けを学ぶ。CH2.lean では、それを使って存在を含む証明を読み、全射の合成へ進む。
