型と命題 II — かつ・または・否定・存在量化

第2章では、全称量化を証明するときに依存関数を作り、仮定として使うときに適用した。第3章では、構成子で項を作り、match で使う仕組みを学んだ。この章では、この二つを組み合わせて数学の証明を読む。

中心となる例は全射の合成である。証明を数学の言葉で書き、どこで対象や証明を受け取り、どこで新しい証明を作ったかを確かめる。存在を使うもう一つの例として偶数の和を読み、その後、全単射、二つの場合の扱い、否定へ進む。

1. 存在の証明と全射の合成

「条件を満たす対象が存在する」と示すには、対象を一つ挙げ、その対象が条件を満たすことを示す。選んだ対象を、ここでは証人と呼ぶことにする。例えば、自然数で 2 に等しいものが存在することは、次のように証明できる。

def exists_eq_two : ∃ n : Nat, n = 2 := Exists.intro 2 rfl

∃ は \exists で入力する。Exists.intro は存在の証明を作る構成子であり、ここでは証人 2 : Nat と、その性質の証明 rfl : 2 = 2 を受け取っている。

第3章の (n : Nat) × B n の項が、n と B n の項からなる依存する組だったことを思い出そう。今度は B n の役割を命題 n = 2 が担い、第二成分としてその命題の証明を渡す。存在の証明も、対象と、その対象についての保証からなる依存する組として読める。これは項の作り方の対応であり、Lean の Exists と Sigma が同じ型だという意味ではない。

任意の自然数の二倍は偶数

自然数 n が偶数であることを、n = 2 * k となる自然数 k が存在することとして定義する。

def IsEven (n : Nat) : Prop := ∃ k : Nat, n = 2 * k

任意の n に対して 2 * n は偶数である。証人に n 自身を選べばよい。

def even_two_mul : ∀ n : Nat, IsEven (2 * n) :=
  fun n => Exists.intro n rfl

外側の fun n => … は全称量化の証明を作る。本体の Exists.intro n rfl は、受け取った n に対する存在の証明を作る。根拠に必要な型は 2 * n = 2 * n なので、rfl が使える。

n + n の場合に必要な等式

n + n が偶数であることも、証人に n を選んで示せる。今度は根拠として n + n = 2 * n の証明が必要である。

#check Nat.two_mul
Nat.two_mul (n : Nat) : 2 * n = n + n
def even_double : ∀ n : Nat, IsEven (n + n) :=
  fun n => Exists.intro n (Eq.symm (Nat.two_mul n))

Nat.two_mul n の等式の向きを Eq.symm で逆にして渡した。構成子を適用するときにも、その引数に要求される型を読む手順は変わらない。この算術の定理を再帰から証明する説明は、03_InductiveTypes.lean 4節にある。

全射どうしの合成は全射

$f:A\to B$ と $g:B\to C$ が全射なら、$g\circ f$ も全射である。まず、数学の証明を読もう。

証明。 $c\in C$ を任意に取る。$g$ の全射性から、$g(b)=c$ となる $b\in B$ を取れる。さらに $f$ の全射性から、$f(a)=b$ となる $a\in A$ を取れる。すると $g(f(a))=g(b)=c$ である。よって、$c$ に送られる元として $a$ を取ればよい。∎

対象を選ぶ順序に注目しよう。最初に c を受け取り、それから b、さらに a を使っている。二つ目の存在を使う際には、一つ目から得た b が必要である。

全射性という保証に名前を付ける

全射であるとは、行き先のどの対象にも、それに送られる元があることである。 f と g の全射性の証明を、それぞれ hf、hg と名付ける。

hf : ∀ b : B, ∃ a : A, f a = b
hg : ∀ c : C, ∃ b : B, g b = c

結論の型は、次のようになる。

∀ c : C, ∃ a : A, g (f a) = c

外側の全称量化を依存関数型の記法に戻すと、同じ型を次のようにも書ける。

hf : (b : B) → (∃ a : A, f a = b)
hg : (c : C) → (∃ b : B, g b = c)
結論 : (c : C) → (∃ a : A, g (f a) = c)

受け取る b や c に応じて、返す存在命題が変わる。外側の全称量化には fun c => … で答える。その本体では、証人 a と、g (f a) = c の証明を構成子に渡せばよい。

存在の証明から、証人と根拠を使う

hg に c を適用すると、hg c : ∃ b : B, g b = c が得られる。存在の構成子に応じて match し、証人と根拠に名前を付ける。

match hg c with
| Exists.intro b hb => …

この枝では b : B と hb : g b = c が使える。次に hf b を適用し、その存在の証明を同じように match すると、 a : A と ha : f a = b が使える。

ここで選んだ a に対して結論の等式を証明し、存在の構成子で包み直す。 match の枝から返すのは、最初に求められた存在命題の証明である。

二つの存在を使って、結論の存在を作る

数学の証明と同じ順に、関数適用・場合分け・構成子を組み合わせる。

def comp_surjective (A B C : Type) (f : A → B) (g : B → C)
    (hf : ∀ b : B, ∃ a : A, f a = b)
    (hg : ∀ c : C, ∃ b : B, g b = c) :
    ∀ c : C, ∃ a : A, g (f a) = c :=
  fun c =>
    match hg c with
    | Exists.intro b hb =>
      match hf b with
      | Exists.intro a ha =>
        Exists.intro a (Eq.trans (congrArg g ha) hb)

hf b は b を取り出した枝の中で使う。そのため match も入れ子になる。

最後の構成子に何を渡したか

最後の枝では ha : f a = b と hb : g b = c が使える。まず、第2章で学んだ等式の操作の型を追う。

congrArg g ha : g (f a) = g b
Eq.trans (congrArg g ha) hb : g (f a) = c

証人を a と決めると、Exists.intro の第二引数に必要なのは g (f a) = c の証明である。いま作った項がその型を持つので、構成子を適用できる。

Exists.intro a (Eq.trans (congrArg g ha) hb) :
  ∃ a : A, g (f a) = c

この本体をどの c に対しても返すので、外側の fun が要求された全称命題の証明になる。

全称量化と存在量化の二つの向き

全射の合成で使った四つの操作を、ここで整理しよう。

命題（型）その証明（項）作るとき使うとき
∀ x : A, P x各 x に P x の項を返す依存関数fun x => …対象を渡して関数適用する
∃ x : A, P x一つの x と、その P x の証明の組Exists.intro x hmatch で証人と根拠を使う

全称の証明は、型の族の各型に項を返す依存関数である。存在の証明は、依存和の組と対応する形で、一つの対象とその対象についての証明を構成子でまとめる。

全称を使うときは「この対象についての保証を取り出す」。存在を使うときは「保証された対象を一つと、その根拠を使って、続きの証明をする」。どちらも、持っている証明の型に応じた使い方である。

✏ 練習

  1. $f:A\to B$ が右逆 $g:B\to A$ を持つ、すなわち hfg : ∀ b : B, f (g b) = b があるとする。 ∀ b : B, ∃ a : A, f a = b を証明する関数 surjectiveOfRightInverse を書け。証人には何を選ぶか。
解答 50 
def surjectiveOfRightInverse (A B : Type) (f : A → B) (g : B → A)
    (hfg : ∀ b : B, f (g b) = b) :
    ∀ b : B, ∃ a : A, f a = b :=
  fun b => Exists.intro (g b) (hfg b)

b を受け取り、証人に g b を選ぶ。その根拠に要求される型は f (g b) = b であり、hfg b が与える。

偶数と偶数の和は偶数

証明。 $n,m$ を偶数とする。$n=2k$、$m=2l$ となる自然数 $k,l$ を取れる。すると $n+m=2k+2l=2(k+l)$ だから、$n+m$ は偶数である。∎

仮定に hn : IsEven n、hm : IsEven m と名前を付ける。まず一つ目の存在の証明を使う。

match hn with
| Exists.intro k hk => …

この枝では k : Nat と hk : n = 2 * k が使える。その中で、二つ目の存在の証明も使う。

match hm with
| Exists.intro l hl => …

今度は l : Nat と hl : m = 2 * l も使える。結論の証人には k + l を選ぶ。その根拠として必要なのは n + m = 2 * (k + l) の証明である。

等式の連鎖を項で書く

数学の式変形 $n+m=2k+2l=2(k+l)$ を、型を確かめながら組み立てる。まず hk と hl を順に使って、左端から真ん中への等式を作る。

congrArg (fun x => x + m) hk : n + m = 2 * k + m
congrArg (fun x => 2 * k + x) hl : 2 * k + m = 2 * k + 2 * l

この二つを Eq.trans でつなぐと、n + m = 2 * k + 2 * l の証明になる。次に、分配法則の証明として標準環境に用意されている Nat.mul_add を使う。

#check Nat.mul_add
Nat.mul_add (n m k : Nat) : n * (m + k) = n * m + n * k

この定理も関数として使う。2、k、l を渡すと 2 * (k + l) = 2 * k + 2 * l の証明が得られる。その向きを Eq.symm で逆にし、先ほどの等式に Eq.trans でつなぐ。これで数学の等式の連鎖全体が、一つの証明の項になる。

偶数の和の証明を完成させる

証人 k + l と、組み立てた等式の証明を Exists.intro に渡そう。

def isEven_add {n m : Nat} (hn : IsEven n) (hm : IsEven m) : IsEven (n + m) :=
  match hn with
  | Exists.intro k hk =>
    match hm with
    | Exists.intro l hl =>
      Exists.intro (k + l)
        (Eq.trans
          (Eq.trans (congrArg (fun x => x + m) hk)
            (congrArg (fun x => 2 * k + x) hl))
          (Eq.symm (Nat.mul_add 2 k l)))

二つの match で仮定の存在を使い、最後の Exists.intro で結論の存在を作った。構成子の第二引数は長い項だが、部分項の型を追えば、必要な n + m = 2 * (k + l) の証明だと確かめられる。

✏ 練習

  1. 任意の自然数 n について、IsEven n → IsEven (n + 2) を証明せよ。 2 の偶数性を Exists.intro で示し、本文の isEven_add を使うこと。
解答 51 
def isEven_add_two : ∀ n : Nat, IsEven n → IsEven (n + 2) :=
  fun _ hn => isEven_add hn (Exists.intro 1 rfl)

2 = 2 * 1 は計算で一致するので、証人 1 と rfl で IsEven 2 が示せる。偶数の和についての関数に二つの証明を渡せばよい。

2. かつ — 全単射の合成

写像が全単射であるとは、単射であり、かつ全射であることである。この二つを一緒に保証することを、証明の組として表そう。

def IsBijective (A B : Type) (f : A → B) : Prop :=
  (∀ x y : A, f x = f y → x = y) ∧ (∀ b : B, ∃ a : A, f a = b)

∧ は \and で入力する。「かつ」の構成子は And.intro で、左側と右側の証明を両方受け取る。

全単射性を示すには、単射性と全射性を示して And.intro に渡す。全単射性を使うには、match の And.intro h_inj h_surj の枝で、二つの証明に名前を付ける。

全単射どうしの合成は全単射

証明。 $f$ と $g$ が全単射なら、どちらも単射なので $g\circ f$ は単射である。また、どちらも全射なので $g\circ f$ は全射である。よって、合成は全単射である。∎

単射性については、第2章と同じように g の単射性、次に f の単射性を使う。全射性については、この章の comp_surjective に必要な仮定を渡す。

hf から hfi と hfs、hg から hgi と hgs を取り出す。 hgi と hfi を順に適用して単射性の証明を作り、全射性の証明と組にする。

全単射の合成の証明項

def comp_bijective (A B C : Type) (f : A → B) (g : B → C)
    (hf : IsBijective A B f) (hg : IsBijective B C g) :
    IsBijective A C (fun x => g (f x)) :=
  match hf with
  | And.intro hfi hfs =>
    match hg with
    | And.intro hgi hgs =>
      And.intro (fun x y h => hfi x y (hgi (f x) (f y) h))
        (comp_surjective A B C f g hfs hgs)

二つの match で仮定を使い、最後の And.intro で結論を作った。各成分を取り出す関数 And.left hf と And.right hf を使う書き方もある。いずれも、二つの証明が入っているという同じ情報を使っている。

✏ 練習

  1. f : A → B、g : A → C と b : B、c : C に対して、 ∃ a : A, f a = b ∧ g a = c から ∃ a : A, f a = b を証明せよ。二種類の構成子を match で使い、必要な根拠だけを取り出すこと。
解答 52 
def existsFirst (A B C : Type) (f : A → B) (g : A → C) (b : B) (c : C)
    (h : ∃ a : A, f a = b ∧ g a = c) : ∃ a : A, f a = b :=
  match h with
  | Exists.intro a habc =>
    match habc with
    | And.intro hab _ => Exists.intro a hab

証人 a はそのまま使い、二つの根拠のうち左側の hab : f a = b を渡す。

3. または — 二つの場合を扱う

$x=a$ または $x=b$ なら、$f(x)=f(a)$ または $f(x)=f(b)$ である。これを証明してみよう。∨ は「または」で、\or と入力する。

証明。 $x=a$ の場合、等式の両辺に $f$ を適用して $f(x)=f(a)$ を得る。$x=b$ の場合も同様に $f(x)=f(b)$ を得る。どちらの場合も結論のいずれかが成り立つ。∎

「または」を示すには、左の証明を Or.inl に渡すか、右の証明を Or.inr に渡す。「または」を使うには、どちらの構成子で作られた場合にも答えを用意する。第3章の直和を使う場合分けと同じ形である。

またはの証明を match で使う

def imageTwoPoints (A B : Type) (f : A → B) (x a b : A)
    (h : x = a ∨ x = b) : f x = f a ∨ f x = f b :=
  match h with
  | Or.inl hxa => Or.inl (congrArg f hxa)
  | Or.inr hxb => Or.inr (congrArg f hxb)

左の枝では hxa : x = a が使える。 congrArg f hxa : f x = f a を作り、結論の左側の証明として Or.inl に渡す。右の枝では f x = f b の証明を Or.inr に渡す。

match 全体が返す型は、どちらの枝でも同じ f x = f a ∨ f x = f b である。

✏ 練習

  1. $f:A\to B$ を単射とする。f x = f a ∨ f x = f b から x = a ∨ x = b を示せ。単射性の証明を hf : ∀ x y : A, f x = f y → x = y として受け取ること。
解答 53 
def preimageTwoPoints (A B : Type) (f : A → B)
    (hf : ∀ x y : A, f x = f y → x = y) (x a b : A)
    (h : f x = f a ∨ f x = f b) : x = a ∨ x = b :=
  match h with
  | Or.inl hxa => Or.inl (hf x a hxa)
  | Or.inr hxb => Or.inr (hf x b hxb)

各枝で単射性を適用し、結論の対応する構成子へ証明を渡す。

4. 否定 — 等しいと仮定して矛盾を作る

False は、構成子を持たない命題である。第3章で自作した空の型 MyEmpty に対応する。 False の証明を受け取ったとすると、False.elim で任意の命題の証明を返せる。

¬ は \not で入力する。「ある命題ではない」とは、その命題の証明を受け取ったら False の証明を返せる、という型で表す。例えば x ≠ y は x = y → False のことである。

したがって、否定を示すときも関数を作り、否定を使うときも適用する。新しい否定用の構成子を使うのではなく、第2章の「ならば」の読み方を使っている。

単射性と否定を組み合わせる

証明。 $f$ を単射とし、$x\ne y$ とする。もし $f(x)=f(y)$ なら、単射性から $x=y$ となって仮定に矛盾する。したがって $f(x)\ne f(y)$ である。∎

def injectivePreservesNe (A B : Type) (f : A → B)
    (hf : ∀ x y : A, f x = f y → x = y)
    (x y : A) (hne : x ≠ y) : f x ≠ f y :=
  fun h => hne (hf x y h)

結論の型は f x = f y → False なので、まず h : f x = f y を受け取る。 hf x y h : x = y に hne : x = y → False を適用すると、本体の型が False になる。ここでは二重否定から元の命題を取り出す背理法は使っていない。

✏ 練習

  1. 任意の写像 $f:A\to B$ について、f x ≠ f y ならば x ≠ y であることを示せ。単射性は仮定しない。x = y と仮定したとき、congrArg で何が得られるか考えよ。
解答 54 
def neOfImageNe (A B : Type) (f : A → B) (x y : A)
    (hne : f x ≠ f y) : x ≠ y :=
  fun h => hne (congrArg f h)

h : x = y から congrArg f h : f x = f y が得られ、それを hne に渡すと False が得られる。

帰納型の異なる構成子

第3章で述べた「異なる構成子は等しくない」という性質も、否定の証明として書ける。標準の帰納型 Bool に対する Bool.noConfusion を使おう。

def bool_true_ne_false_by_noConfusion : Bool.true ≠ Bool.false :=
  fun h => Bool.noConfusion h

h : Bool.true = Bool.false を仮定すると、Bool.noConfusion h : False が得られる。この矛盾を返す関数が、不等号 ≠ の証明になっている。この道具を使った別の例を、次の補足で見よう。

補足: 構成子が別々であることと noConfusion

noConfusion は、帰納型の宣言に伴って作られる道具である。異なる構成子の項は等しくないことと、同じ構成子の項が等しければ中身も等しいことを証明できる。

def succ_injective_by_noConfusion {m n : Nat} (h : Nat.succ m = Nat.succ n) : m = n :=
  Nat.noConfusion h (fun h' => h')

この例では、中身が等しいという保証 h' : m = n を受け取り、そのまま返す関数を渡している。

#print axioms Bool.noConfusion
'Bool.noConfusion' does not depend on any axioms

この道具も新たな公理ではなく、帰納型の原理から証明されている。

5. 証明を作る・証明を使う

同じ命題でも、結論として証明する場面と、仮定として使う場面とでは操作が違う。

命題の形証明するとき仮定として使うとき
ならば・全称fun で関数を作る証明や対象を適用で渡す
存在Exists.intro で証人と根拠をまとめるmatch で証人と根拠を使う
かつAnd.intro で両方の証明をまとめるmatch などで両方の証明を使う
またはOr.inl または Or.inr で作るmatch で両方の場合を扱う
否定仮定から False を返す関数を作るその仮定の証明を適用して False を得る

数学の証明で行う操作を、関数・構成子・場合分けで表した。その読み替えを人間が理解し、完成した項の型を機械が検査する、という第2章の見方につながる。

6. 型検査が証明の検査になる

全称や存在、単射や全射の合成で行った型の照合から、証明検査の意味を整理しよう。

証明は項なのだから、「証明が正しいか」は「項が主張どおりの型を持つか」という 型検査の問題になる。型検査は機械的な計算であり、Lean はすべての宣言に対してそれを実行している。だから、ファイルがエラーなしに受理された時点で、そこに書かれた全定理の検査は済んでいる。

この主張には但し書きが3つある。第一は、この検査が宣言済みの公理に相対的であること。 axiom bad : 0 = 1 のような宣言もエラーなく受理できてしまうので、「何を公理として使ったか」は #print axioms で別に監査する必要がある。第二は、証明を保留する印 sorry がエラーではなく警告になること（依存すると #print axioms に sorryAx が現れる）。だから正確には、「エラーがなく、sorry の警告もなく、#print axioms の結果が納得できる公理だけ」を見る。06_Topology.lean の末尾で、主定理に対してこの監査を実行する。第三は、この監査の例を見たあとで述べる。

#print axioms comp_surjective
'comp_surjective' does not depend on any axioms

この証明は追加の公理に依存していない。

その検査は、形式化したかったものの検査か

第三の但し書きは、公理や sorry の監査を済ませても残る。型検査が確かめるのは「項が主張どおりの型を持つ」ことだけで、 その型が、本当に確かめたかった主張であるかは型検査の外側にある。問題は3点に分けられる。

  1. 形式化の問題。「単射どうしの合成は単射」という気持ちを ∀ x y, g (f x) = g (f y) → x = y と書いたとき、式が気持ちを正しく写しているかは、書いた人が判断するほかない。
  2. 実装の問題。エラボレータやカーネルにバグがあれば、誤った項を受理しうる。カーネルを小さく保ち、独立した検査器で再検査する対策はあるが、ゼロにはならない。
  3. 理論の解釈の問題。証明を返す関数の型をなぜ「ならば」や「すべての」と読んでよいのか、型をなぜ集合のように扱ってよいのか。型検査を通った項が一貫した意味を持つ、という仮定がここにある。この仮定が正しければ、矛盾が導けないことも従う。

この教材では以後、これらを認めたうえで「エラーなしに受理された」ことを検査済みと呼ぶ。

証明を考える順序と、出来上がった項を読む順序

証明を考えるときは、まず結論から必要な入力と出力を見る。単射性なら二つの対象と像の等式を受け取り、対象どうしの等式を返す必要がある。その出力を作れる仮定や道具を探し、必要な証明を組み合わせる。

出来上がった項を読むときは、内側の適用から型を追える。単射の合成なら、hg (f x) (f y) h : f x = f y、次に hf x y (hg (f x) (f y) h) : x = y である。全射の合成なら、証人 a に対して g (f a) = c の証明を作り、構成子に渡せることを確かめた。どの場合も、部分項の型を求め、次の関数や構成子が要求する入力型と照合している。

一段を飛ばすと型が合わない

単射の合成の本体を hf x y h としてしまうと、受理されない。 hf x y が要求するのは f x = f y の証明だが、h は g (f x) = g (f y) の証明だからである。紙の証明で「$g$ の単射性を使う」という一段を飛ばしたことが、引数の型の不一致として検出される。

省略を補う処理と、完成した項の検査

ソースコードから証明の検査までは二段階ある。 エラボレータは記法を展開し、暗黙引数や型の情報を補って項を組み立てる。 カーネルは、その完成した項が指定された型を持つかを検査する。省略をうまく補うことと、出来上がった項が正しいことを確かめることは、役割が異なる。

例えば Nat.sub_add_cancel は、自然数の引き算で引く数が大きすぎないという仮定を要する。

#check Nat.sub_add_cancel
Nat.sub_add_cancel {n m : Nat} (h : m ≤ n) : n - m + m = n

n - 1 + 1 = n を全自然数で示そうとして、必要な仮定を _ にするとどうなるか。

def sub_one_add_one : ∀ n : Nat, n - 1 + 1 = n :=
  fun n => Nat.sub_add_cancel _

この _ に必要なのは 1 ≤ n の証明であり、エラボレータはそれを補えない。しかも n = 0 が反例なので、任意の n に対してこの穴を埋める証明は書けない。一方、その仮定を正しく受け取れば、項を完成させられる。

def sub_one_add_one (n : Nat) (h : 1 ≤ n) : n - 1 + 1 = n := Nat.sub_add_cancel h

省略を補った後にも、完成した項が宣言の型を持つかが検査される。ただし、その宣言自体が意図した数学の主張を表すかは、人間が読む必要がある。

補足: 理論を解釈する前提

第3点について、Lean の理論（帰納型・宇宙の階層・Prop・後で見る公理を含む）を ZFC に相対的に解釈するモデルは知られている。ただしそのためには、ZFC に到達不能基数を（宇宙の階層の段ごとに1つずつ、可算無限個）加える必要があり、これは ZFC より真に強い仮定である。

7. ✏ 練習 — 章末問題

数学の証明を書き、仮定と結論の型を確かめてから、Leanの項にしよう。

  1. 三つの全射 $f:A\to B$、$g:B\to C$、$k:C\to D$ の合成が全射であることを証明せよ。本文の comp_surjective を二回使う解答を書け。各適用に渡す型と写像を明示すること。
解答 55 
def threeCompSurjective (A B C D : Type)
    (f : A → B) (g : B → C) (k : C → D)
    (hf : ∀ b, ∃ a, f a = b) (hg : ∀ c, ∃ b, g b = c)
    (hk : ∀ d, ∃ c, k c = d) :
    ∀ d, ∃ a, k (g (f a)) = d :=
  comp_surjective A C D (fun a => g (f a)) k
    (comp_surjective A B C f g hf hg) hk

内側の適用は A → C の全射性、外側の適用は A → D の全射性を証明する。
