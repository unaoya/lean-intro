# 講義スライドの区切り設定

本文と解答は `src/*.lean` を通読版・スライド版で共有する。スライド専用の原稿コピーは作らない。
冒頭の目的・目標・構成は `tools/lean2html.py` の共通本文から生成し、
`Index.json` で区切る。スライドの `index.html` とスライドPDFの冒頭にも同じ内容が入る。
`docs/` と `pdf/` は生成物なので直接編集しない。

## 現在の編集方針

01_TypesAndTerms・02_Forall・03_InductiveTypes・04_Exists・05_MathematicalTools は、本文と解答を読み、話題・例・証明の筋道に沿って
全ページの境界を各章の JSON に設定している（`version: 2`）。
生成器はこの設定をそのまま使い、文字数や高さの推定で勝手に改ページしない。

- 同じ話題の説明・定義・結果は、読める大きさで収まる限り同じページに置く。
- ページ内では、段落・コードブロック・出力ブロック・箇条書き・表を、それぞれひとまとまりで順に表示する。
- 見出しは最初の説明と一緒に出す。練習の見出しだけ、解答ラベルだけの表示段階は作らない。
- 問題の直後にその解答を置く。短い問題は同じページ、長い問題は定義や推論の切れ目でページを分ける。
- 通常は文ごと・コードの行ごと・表の行ごとには分割しない。
- 原稿を改稿したら、アンカーの一致だけでなく、全表示後のページの収まりを HTML・PDF で確認する。
  収まらなくなったら、内容を読んで境界を再編集する。本文の削除や文字の縮小で対処しない。

06_Topology・07_Exercises・08_Real・09_Ascoli・10_AscoliReal・11_Covering・12_CoveringSpace・13_FundamentalGroupoid はスライド生成の対象外。通読版 HTML・PDF には含める。
対象外の章は `tools/lean2html.py` の `SLIDE_EXCLUDED_CHAPTERS` で管理する。

標準ビルドでは、補足・先取りの注記ブロックをスライド HTML・PDF から省く。
`python3 tools/lean2html.py --include-slide-notes` で含められる。
その場合、注記の元の位置で本筋のページをいったん区切り、注記後に続きを表示する。
注記自体には従来の自動分割を使う。次の `lake build` では標準の省略版に戻る。
通読版はこの設定によらず注記を含む。

## ページと表示段階の指定

```json
{
  "version": 2,
  "pages": [
    {
      "at": {"section": "01_TypesAndTerms.intro", "tag": "h1", "starts": "型と項 I"},
      "id": "introduction",
      "label": "導入"
    },
    {
      "at": {"section": "Intro1.terms-types", "code": "#check Nat"},
      "id": "nat-is-a-term",
      "label": "Nat も型を持つ項"
    }
  ]
}
```

`pages` は章の冒頭から順に、全ページの開始位置を列挙する。
各ページには、次の開始位置の直前までが入る。
`id` は英小文字・数字・ハイフンの固定名、`label` は目次や PDF ヘッダーの表示名で、両方とも必須。
URL は `01_typesandterms.html#01_typesandterms-nat-is-a-term/1` のようになる。末尾の数字は表示段階であり、原稿の連番指定ではない。

各本文ブロックは順に追加表示される。普通の箇条書き・番号付きの推論・表も、全体を一度に表示する。
通常の `splits` はページ境界に必要な切れ目だけにする。
01_TypesAndTerms の「期待される型を上から伝える」では、2つの箇条書きを個別に示す指定も置いている。

`splits` は、長いブロックの途中にページ境界を置く場合など、明示的に分割するための指定。
`before` の各文字列の直前で次の表示段階に進む。文字列は対象のブロック内にちょうど1回現れる必要があり、
原稿の順に指定する。ページ境界を伴わない分割は、細かい段階表示が個別に必要な場合だけ指定する。
ここは改行や空白を含めてそのまま照合するので、インデントも使える。
構文の強調表示や数式・インラインコードを保つため、それらの途中では切らない。

長いコードなどの途中からページを始める場合は、`splits` に置いた文字列を `at.part` にも書く。
例えば `"part": "#check comp_surjective"` とすると、そのコマンドから次のページになる。
`part` がないアンカーは常に元のブロックの最初の部分を選ぶ。

## 配置と余白

HTML・PDF ともに、未表示の内容も含めたページ全体の高さを基準に、短いページを上下中央に配置する。
段階を進めても、すでに表示した本文の位置は動かさない。長いページは上に寄せ、必要に応じて
行間・段落間隔を2段階で詰める。文字サイズとページ境界はこの処理では変更しない。
HTML は画面のリサイズ・全画面切替でも配置を更新し、小さい画面で収まらない場合はスクロールできる。

比較を左右に並べる場合は、ページ定義に `column_at` を追加し、右列の開始ブロックをアンカーで選ぶ。
例えば、01_TypesAndTerms の `double 21` と `double true` は同じページの左列・右列に置いている。

```json
"column_at": {"section": "Intro1.functions", "tag": "p", "starts": "一方、double true を調べると、"}
```

表示順は左列から右列で、各ブロックを1段階ずつ表示する。狭い画面では1列に戻る。
列の境界も本文の途中や連番では指定せず、新しいブロックの開始を選ぶ。

## アンカー

`at` は次の条件を組み合わせ、本文の1か所を選ぶ。ブロックの連番や練習の表示番号には依存しない。

| 条件 | 意味 |
| --- | --- |
| `section` | 見出しの固定ラベル（`sec-` を除く）。冒頭は `01_TypesAndTerms.intro` など |
| `heading` | 見出しの文字列 |
| `code` | 実際の Lean コードに含まれる1行。出力や引用コードは対象外 |
| `declaration` | `def`・`theorem`・`class`・`structure`・`inductive` などの宣言名 |
| `starts` | ブロックの先頭の文字列 |
| `text` | ブロックの全文 |
| `tag` | `p`・`pre`・`h3` などの HTML 要素名 |
| `class` | `lean`・`quote`・`answer-heading` などの種別 |
| `answer` | 解答中を選ぶとき `true`。省略時は本文のみ |
| `question` | 対応する問題文の先頭。似た解答を表示番号によらず区別する |
| `next` | 直後のブロックの先頭。「✏ 練習」のように繰り返される見出しを区別する |
| `part` | `splits` で指定した文字列。その位置から始まる部分を選ぶ |

`at` の文字列条件は空白・改行を正規化して比較する（`code` は行として比較）。
改稿で一致しなくなった場合、複数に一致した場合、境界の順序が違う場合はビルドを失敗させる。
前に段落を挿入しても、後ろの設定が連鎖的にずれることはない。
生成時には本文と解答の文字が順序通りに全部残っていることも検査する。

設定のない新しい章、および旧 `version: 1` の `rules` は従来の自動分割を使う。
現在の5章の本筋はすべて `version: 2` なので、この自動分割は使われない。

## 練習と PDF

本文の「✏ 練習」は 01_TypesAndTerms から 06_Topology まで、補足・先取り内も含めて通し番号を付ける。
通読版・スライド版で番号を共有するため、補足を省いたスライドでは欠番があり得る。
Lean 内の問題番号と `SOL 固定ラベル:問題番号` は対応付け用の局所番号として残す。
07_Exercises・08_Real・09_Ascoli・10_AscoliReal・11_Covering・12_CoveringSpace・13_FundamentalGroupoid の別形式の「問題」はこの通し番号の対象外。

通読版 HTML は解答を折り畳み、通読版 PDF は開く。
スライド PDF は HTML の各表示段階につき1ページを生成する。
同じ画面で段階的に表示するため、PDF の総ページ数はスライド画面数より多い。

HTML だけの確認は `python3 tools/lean2html.py --no-pdf`。
Lean の検査と両形式の HTML・PDF の生成は `lake build`。
生成器の検査は `python3 -B -m unittest discover -s tools -p 'test_*.py'`。
