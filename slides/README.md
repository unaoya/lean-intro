# 講義スライドの区切り設定

本文は `src/*.lean` のみで管理する。スライド用のコピーは不要。
生成器は通読版と同じ HTML 本文を受け取り、補足・解答を含めて文字を保持したまま分割する。
長いコードは行の境目、文章はなるべく文の境目で分ける。文字を縮めて詰め込まない。

`slides/Intro1a.json` のように章名の JSON を置くと、自動分割を調整できる。
設定のない章も自動生成される。JSON に本文そのものを書き直す必要はない。

```json
{
  "version": 1,
  "rules": [
    {
      "at": {"section": "Intro1.terms-types", "code": "#check 3"},
      "id": "check-nat",
      "label": "#check 3"
    },
    {
      "at": {"section": "Intro1.dependent-functions", "declaration": "constTuple"},
      "id": "const-tuple"
    }
  ]
}
```

`at` は段落の連番ではなく、本文の意味を手がかりに指定する。
次の条件を複数書くと、すべてに一致するブロックを選ぶ。

| 条件 | 選ぶもの |
| --- | --- |
| `section` | 見出しの固定ラベル（`sec-` を除く）。章の冒頭は `Intro1a.intro` など |
| `heading` | 見出しの文字列 |
| `code` | 実際の Lean コードに含まれる1行。出力欄や説明中の引用コードは対象外 |
| `declaration` | `def`・`theorem`・`lemma`・`class`・`structure`・`inductive` の宣言名 |
| `starts` | 段落などの先頭の文字列 |
| `text` | ブロックの全文 |
| `tag` | `p`・`pre`・`h3` などの HTML 要素名 |
| `kind` | `main`・`optional`・`preview` |

本文の空白・改行の違いは、文字列条件では正規化する（`code` は行として比較）。
各条件は必ず1ブロックだけに一致しなければならない。
改稿で一致しなくなった場合や、同じ文が増えて曖昧になった場合は、ビルドが具体的な条件を示して失敗する。
前に段落を挿入しても、後ろの設定が連鎖的にずれることはない。

区切りは `break` で指定する。

- `page`（省略時）: このブロックから新しい画面。
- `step`: 同じ画面内で、次の操作によって表示する。
- `keep`: 通常なら見出し・コードの前で分ける箇所を、同じ表示段階にまとめる。

ただし画面の上限、章節や補足の境目、解答の後では、`step`・`keep` でも新しい画面に分ける。
コードの直後の出力欄は、設定なしでも次の表示段階になる。

`id` は `page` でだけ指定できる英小文字・数字・ハイフンの固定名。
例では URL が `intro1a.html#intro1a-check-nat/1` になる。末尾の数字は表示段階で、区切りの指定には使わない。
`label` は目次に表示する名前。省略すると見出しから作る。
自動分割した画面の ID は内容から生成するため、長期的なリンクには明示的な `id` を使う。

Intro1a は4節全体について、`Tuple`・`constTuple` を含む現在の本文に合わせて調整している。
以後の章も、講義しながら必要な箇所だけこの方式で上書きできる。

確認には `python3 tools/lean2html.py --no-pdf`、全形式の生成と Lean の検査には `lake build` を使う。
`docs/` と `pdf/` は生成物なので直接編集しない。
