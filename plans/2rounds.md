# 2往復構成案 — 依存関数を先に学び、証明へ進む

2026-09-23 時点の改訂計画。[3往復案](3rounds.md) に代わる検討の基準とする。
この計画による本文の分割・並べ替えはまだ行っていない。
以下の「現行 §N」は、分割前の `src/Intro1.lean`・`src/CH.lean` の節を指す。

## 目的と方針

教材の目標は、Lean の項の型を追って読めるようになり、同じ型検査が証明の検査に
なることを納得することである。現行の Intro1 全体を読み終える前に、数学の証明を
実際に読む機会を置く。

**帰納型より先に依存関数型を導入し、Intro1 と CH をそれぞれ2分割する。**

- 1往復目: 関数・依存関数を学び、ならば・全称の証明を読む。
  「単射どうしの合成は単射」まで進み、型検査が証明の検査になることを確かめる。
- 2往復目: 帰納型・structure を学び、かつ・または・矛盾・存在の証明を読む。
  偶数の和や全射の合成を読み、等式の仕組みと証明検査の全体像を整理する。

一般の命題 `P`・`Q` を扱う例は維持する。依存関数を避けるために、論理的な筋道が
見えにくい具体的な数式へ置き換えない。最初の証明編で、ふつうの数学の証明から
論理式・証明項までをたどる経験を作る。

3往復案に比べ、最初の証明までに依存関数の説明が加わる。その分、命題を引数として
受け取る宣言も全称量化も正面から説明でき、単射の例を早い段階で扱える。
存在を全称より前に置く必要もなくなる。

## Intro1a — 関数と依存関数まで

### 基本の順序

1. 現行 §1「項と型」、§2「def」、§3「関数」を土台にする。
   `Nat`・`Bool` などは Prelude の既存の型として使い、その定義の作り方は後半へ回す。
2. §3 の `Map : Type → Type → Type` で、型も引数や返り値になれることを確認する。
3. 現行 §6 の `idAt (α : Type) (a : α) : α := a` を導入する。
   `idAt Nat : Nat → Nat` と `idAt Bool : Bool → Bool` を比べる。
4. 一般の族 `B : A → Type` と `(a : A) → B a` に進む。
   「型を引数に取ること」だけが依存関数なのではなく、結果の型が入力によって
   決まることが本質だと説明する。族の各点で項を返す、という集合族の直積の見方を添える。
5. 依存する適用の規則を明示する。
   `f : (a : A) → B a` と `x : A` から `f x : B x` を得る。
   現行 §3 の `f : A → C` の規則を一般化し、型の中にも実引数を代入することを追う。
6. 明示引数 `( )`・暗黙引数 `{ }` を説明し、CH1 へ進む。

### 導入・例・練習の書き換え

- 現行 §6 冒頭の「前節で依存和を見た」「射影の切断」という導入は使わない。
  依存和との関係は Intro1b の依存するフィールドの説明で回収する。
- 暗黙引数の初出を現行 §4 の `MySum.inl` から移す。
  `idAt` の型引数を暗黙にした関数を使い、引数 `3` から型 `Nat` が補われる例を置く。
  型引数を省略する前に、明示的に渡す形で型の代入を十分に確認する。
- `PointedType.point`・`Pair.mk`・`makePair`・`swapAt`・`idAt Signal` は Intro1b に残す。
  前半の練習には `idAt Nat`・`idAt Bool`・`idAt (Nat → Nat)`・`constAt` などを使う。
- 現行 §1 の証明を使った長い先取り枠は取り除き、CH1 への短い見通しにする。
  `Prop` と「命題も項である」という紹介は残す。
- `_` は未確定の穴、`sorry` は証明などを保留する仕組みとして、出力の読み方に必要な
  最小限を初出で説明する。公理依存の監査は CH1 で行う。
- 証明の前に型を返す関数と、その各点の型の項を返す依存関数を混同させない。
  `Map` と `idAt` の型の違いを読み比べる。

## CH1 — ならば・全称と、証明の検査

### 推奨する流れ

1. 命題は `Prop` の項、その命題を型とする項が証明、という対応を述べる。
   `theorem`・`example` の読み方を説明する。命題を引数にする宣言も、Intro1a の
   依存関数の仕組みで読めることを確認する。
2. 現行 §0 の modus ponens、含意の推移を読む。
   一般の `P`・`Q`・`R` のまま、仮定を使う適用と仮定を受け取る `fun` を追う。
3. 現行 §1 の命題・theorem・rfl の整理、§2 の関数型と含意の対比を置く。
   `rfl` は計算で一致する等式の証明として導入し、Eq の定義は CH2 で説明すると予告する。
4. 全称の小例 `all_refl` を読み、`∀ a, Q a` と依存関数型の対応を説明する。
   述語は「対象を受け取ると命題が決まる関数」として、量化子を使う前後に説明する。
5. 現行 §0 の単射の合成を読む。
   ふつうの証明 → 論理式 → 形式化を意識した版 → 項、の4段をここで初めて通す。
   定義を開いた証明を主例とし、`Function.Injective` による略記も対応づける。
6. 現行 §6 の依存積と全称の整理を置く。
   `mkPi`・`mkForall`・`applyPi`・`applyForall`、述語 `IsZero` と `all_mul_zero` を扱う。
7. 「型検査が証明の検査になる」を回収し、CH1 を一度完結させる。
   正しい例に加えて、仮定を取り違えた項が型の不一致で拒否される小例を置く。
   公理と `sorry` の但し書き、`#print axioms` による確認まで扱う。

### 初出の調整と境界

- `modus_ponens` の練習の出力には、全称の本格的な説明より先に `∀ (P Q : Prop), …`
  が現れる。冒頭で `∀ a, Q a` は `(a : A) → Q a` の命題での表記でもあると短く示す。
  その意味と使い方は `all_refl`・単射の例で丁寧に回収する。
- `Function.Injective` の説明にある「このあと導入する IsEven と同じ」は外し、
  単射の定義を開いた論理式との比較で略記の意味を説明する。
  `⦃ ⦄` の説明はこの略記の補足にとどめる。
- `#check rfl` の `Sort`・宇宙変数まで含む一般形は CH2 の Eq の説明へ回す。
  `#check applyFun Nat.succ 3` の練習は、既習の `double` を使う形へ変更する。
- 公理の注意は未習の `False` を使わず、`axiom bad : 0 = 1` を文章中の例とする。
  本文の環境にこの公理は追加せず、実行する監査には `modus_ponens` などを使う。
- 前処理で省略を補い、完成した項をカーネルが検査するという短い説明を置く。
  インスタンス・タクティクを含む詳説は CH2 に残す。型検査と省略の補完を混同させない。
- 現行 §6 の練習 `all_and` は「かつ」が必要なので CH2 へ移す。
  `0 * n` の再帰と帰納法を説明する補足、およびその補足の確認問題も CH2 へ移す。
- 「主張した Lean の命題の証明を検査すること」と「その命題が意図した数学を表すこと」
  の違いは、最初の証明検査の説明から明記する。

## Intro1b — 帰納型と structure

現行 §4・§5 を中心にし、§7 の総合練習を置く。CH1 で証明を経験した読者に向け、
「関数による証明に、新しい項の作り方・使い方を加える」と導入する。

1. 列挙型と `match`、構成子の引数、型パラメータ、再帰へ進む。
2. structure、組の構成と射影、ドット記法へ進む。
3. `PointedType` で依存するフィールドを導入する。
   `PointedType.point : (p : PointedType) → p.carrier` は既習の依存関数型の実例として読む。
4. 依存するフィールドを持つ組を、族の直和として整理する。
   Intro1a の族の直積との比較や、射影の切断という見方はここで補足できる。
5. 総合練習で型と項を読む力を確認し、CH2 の構成子・場合分けを使う証明へつなぐ。

現行の「依存関数の最初の実物」「次節で説明する」は書き換える。
`MySum.inl` の暗黙引数は初出の説明を繰り返さず、自動生成された構成子への応用として扱う。
前半から移した `Pair`・`PointedType`・`Signal` の練習は、それぞれの定義の後へ置く。

CH 向けの先取り枠も見直す。「仮定として使う・結論として示す」は CH1 の復習として
接続し、構成子の単射性や帰納法原理の詳説は CH2 への短い予告にする。
「これで初めて CH を読む準備が整った」という締めは使わない。

現行 §7 の総合練習は原則ここに残す。関数だけの問題を前半の復習に使う場合も、
同じ問題と解答を二重に掲載しない。記号入力の一覧は参照用の付録として残す。

## CH2 — 構成子・場合分けによる証明と総仕上げ

冒頭で CH1 の関数と適用を短く振り返り、Intro1b で学んだ構成と分解が、今度は
どの証明の手順に当たるのかを示す。次の順序を基準に試作する。

1. **かつ・または・矛盾**（現行 §3〜§5）。
   「かつ」の交換や「または」による場合分けを短い普通の証明として読み、項へ直す。
   型との対比に加え、仮定として使うときと結論として示すときの手順を確かめる。
   `all_and` の練習をここで回収する。
2. **存在を示す・使う**（現行 §0 の後半）。
   `exists_eq_two` で構成子を導入し、`n + n` が偶数である例へ進む。
   `IsEven` はこの例の略記として一度だけ定義する。
   `exists_map`、偶数の和、全射の合成へ進み、現行の数学の例の流れを保つ。
   全射の例では、CH1 の単射の合成を改めて参照し、必要な項の違いを比較する。
3. **依存和・部分型との整理**（現行 §7）。
   `mkSigma`・`mkExists`、`currySigma`・`curryExists`、`Fin`・`last` をまとめて扱う。
   全称も依存関数も既習なので、この節を複数の章に割る必要はない。
   `exists_left` は存在と「かつ」の組み合わせを確かめる練習として残せる。
4. **示すとき・使うときの総まとめ**（現行 §8 と §0 末尾の一覧）。
   型と命題の対照表と、普通の証明の「頭の動き」の一覧を一つの節で整理する。
5. **等式・自然数の命題の仕組み**（現行 §9）。
   Eq・Nat.le の構成子、等式の法則、`noConfusion`、`MyEq` を扱う。
   添字の単一化・依存する `match`・帰納法原理の詳説は、初読では飛ばせる補足を維持する。
6. **証明検査の詳説**（現行 §10 後半）。
   エラボレータとカーネル、仮定を飛ばしたときの穴、穴を使って項を組み立てる方法を扱う。
   CH1 の公理・`sorry` の監査を参照し、Intro2・Top へ接続する。
7. **対応のずれの理由**（現行 §11）。
   証明を区別しないことと除去制限、例外を整理する。

### 補足と注意の置き場所

- 存在の初出で、「別の命題を証明するために `match` で分解できるが、データの組と
  同じように証人を計算用の値として射影できるわけではない」と伝える。
  部分型との比較でもその違いを明示する。制限の理由の詳説だけを末尾へ回す。
- かつ・またはの導入でも、型側との対応があらゆる使い方で同一だとは述べない。
- 「`0 * n` で `rfl` が止まる」補足は、偶数の例で計算と等式の定理を区別する箇所へ移す。
  `IsZero` は CH1 の定義を使い、再定義しない。
- `two_mul_from_scratch` の補足は、等式の連鎖を学んだ偶数の和の後に残す。
  全射の合成へそのまま進めるよう、初読で飛ばせる形を維持する。
- `IsEven` の定義や `exists_map` の初出を不必要に分散させない。
  3往復案のための「存在だけを先に独立させる」再配置は採用しない。

## 参照・解答・import・生成の変更

### 固定ラベルと解答

節を丸ごと移す場合、既存の固定ラベルは保つ。章名と節番号の表示は refcheck で同期する。
一方、**一つの節を分ける場合には、新しい節ラベルと参照の振り分けが必要**である。

- `CH.reading-proofs` は CH1 に残し、CH2 の存在・偶数・全射のまとまりに新しいラベルを付ける。
  `IsEven` を参照する Intro2 の練習などは、新しい定義の所在地へ向ける。
- `Intro1.dependent-functions` は Intro1a に残す。構造を使う例・練習の解答は、
  Intro1b の実際の移動先の節ラベルに変更する。
- `CH.dependent-products` は CH1 に残す。`all_and` と `0 * n` の補足の解答も、
  CH2 の移動先の節ラベルへ変更する。
- `CH.type-checking` は CH1 の核心の節に残し、CH2 の詳細には新しいラベルを付ける。
  Top 冒頭の「カーネル」への参照などは、どちらの説明を指すべきか内容で判断する。
- 各本文に対応する `Intro1aSol`・`CH1Sol`・`Intro1bSol`・`CH2Sol` を作る。
  SOL チャンクは問題と一緒に移し、移動先ラベル・番号・並び・必要な定義を確認する。
  問題の合併や本文への昇格があれば、解答側の重複・余りも整理する。
- 「前節」「次節」「例3」「このあと」「初出」などは自動同期されないため、文章として点検する。

### import の暫定案

- Intro1a: 教材の他の章を import しない。
- CH1: `import Intro1a`。
- Intro1b: `import Intro1a`。CH1 は読書上の前提とし、その定義をコードで使う場合にのみ import を追加する。
- CH2: `import CH1` と `import Intro1b`。
- Intro2: `import Intro1b` と `import CH2`。Top・Extra は既存の連鎖を維持する。
- 解答ファイル: 対応する本文を import する。前の解答で定義した名前への依存も確認し、
  本文の例が解答ファイルを import しないと通らない状態にはしない。

## 実施の順序と確認

1. **比較の基準を確保する。** 現在の作業ツリーには本文・生成物の変更があるため、
   それらを含む現行版を基準として記録する。main の内容だけを基準にして変更を落とさない。
   旧計画にある Issue #2 の指摘は対応状況を確認し、未対応の事実誤認や初出の不足を先に直す。
2. **別ブランチで試作する。** 作業名は `codex/two-rounds` を候補とする。
   まず Intro1a と CH1 のまとまりを作り、単射の合成と証明検査まで通して読む。

3. **Intro1b と CH2 を再構成する。** 数学の例のつながりを整え、移動した補足・練習を回収する。
   ラベル・解答・import・生成設定は、対応する本文の移動と一緒に更新する。
4. **機械的に確認する。** `python3 tools/check_refs.py --fix` と読み取り専用の検査、
